# 膝关节复测规则与首批案例

## 1. 复测由处理单元生成

页面不能自行决定复测内容。每次处理完成后，决策核心只返回：

- 当前处理直接影响的标准动作；
- 每个动作要更新的指标；
- 是当场复测还是之后复查；
- 是否可以沿用刚才的结果。

## 2. 复测规则

1. 同一个标准动作一次完成，同时更新其范围、分数和动作表现。
2. 主诉和同一个活动方向重合时共用结果，例如“绷直膝盖痛”和“膝伸直范围偏小”。
3. 下楼与膝伸直是两个动作，不能错误合并，但同一处理可能让它们在一轮后一起复测。
4. 已处理区域再次命中时生成 `retest-only` 单元；两次相同动作之间没有新处理，沿用上一条结果。
5. 中间增加了新的松解、关节处理或训练，必须重新复测。
6. 肿胀、压痛和力量不足不在每项手法后反复复测。
7. 主诉分数下降即记录该方向有效，不要求归零。
8. 主诉改善后，后续独立处理不再每项都测主诉；所有处理结束时统一再记录一次。
9. 活动范围未接近健侧时继续未重复候选；专业人员确认被动仍受限时可以进入关节处理。
10. 所有候选结束后仍未完全恢复，保留所有有效方向作为居家和下次重点。
11. 关节松动不能只根据“做过肌肉处理”出现；必须先完成该组处理后的相关动作复测，并且专业人员仍记录到被动范围受限。
12. 主诉已经改善但未归零时，先保存有效方向；处理其他独立问题期间不反复复测主诉，其他问题处理结束后再统一测一次。
13. 已完成的处理只有在它是最新处理且尚缺对应复测结果时，才能重新成为当前步骤；更早的处理不能反复占据流程。
14. 检查发现活动受限但没有局部支持信息时，不猜测肌肉处理，先追加一项位置确认。
15. 位置确认完成但没有找到明确区域时，不重复询问；转入对应方向的主动控制或专业检查。
16. 正常、异常、不知道都代表该方向已经完成一次检查。说不清主诉的基础伸屈检查按“伸直一次、弯曲一次”推进，不因结果正常而重新出现。

## 3. 首批验收案例

### KDC-01｜下楼膝内侧痛，同时伸直受限

输入：右膝内侧下楼酸痛 6/10；主动、被动伸直均小于健侧；大腿外侧更紧。

必须输出：

- “下楼梯”和“下台阶”合并为一个主诉问题；
- 膝伸直保留为独立活动度问题；
- 大腿外侧链只处理一次；
- 一轮后复测下台阶和膝伸直；
- 专业路径中，被动仍受限才出现膝关节处理。

### KDC-02｜主诉就是绷直膝盖疼

输入：伸直膝盖内侧痛 5/10；活动度检查同样发现伸直范围偏小。

必须输出：

- 只形成一个标准动作；
- 复测一次，同时记录分数和范围；
- 不再出现“主诉复测”与“活动度复测”两张卡片。

### KDC-03｜没有新处理的连续复测

输入：刚刚已经复测下台阶为 4/10；下一条规则仍指向同一个下台阶动作，中间没有处理。

必须输出：沿用上一条结果，不显示评分条。

### KDC-04｜增加新处理后再测

输入：下台阶第一次复测 4/10，随后完成另一个未重复肌肉区域处理。

必须输出：重新复测下台阶，不沿用 4/10。

### KDC-05｜力量不足

输入：股四头肌末端力量比另一侧弱，没有当场疼痛动作。

必须输出：转训练，不在每项处理后反复测力量。

### KDC-06｜只有肿胀

输入：急性膝扭伤，安全确认允许继续；髌骨周围肿胀，没有固定疼痛动作。

必须输出：一次肿胀管理；当天晚些时候或下次比较，不生成下楼、下蹲或跑步复测。

### KDC-07｜普通用户主动伸直偏小

输入：普通用户自查，主动伸直比另一侧小，无法检查被动活动。

必须输出：轻柔相关肌肉处理与主动伸膝控制；不让用户自行做关节松动。

### KDC-08｜专业人员确认被动伸直受限

输入：主动、被动伸直都小于健侧；相关肌肉处理后被动仍不足。

必须输出：进入伸直方向关节处理，再一次记录被动、主动和原有症状。

### KDC-09｜主诉改善但伸直仍不足

输入：下台阶由 6/10 降到 3/10，但伸直仍小于健侧。

必须输出：主诉标记改善，保存有效方向；伸直问题仍存在，继续处理或训练。

### KDC-10｜说不清或不知道

输入：用户只能确认膝内侧不舒服，动作说不清；部分检查选择不知道。

必须输出：保留问题，不生成空方案；选择一个简单、低风险且有价值的检查，未知结果不触发处理。

## 4. 当前自动测试

`tests/unit/domain/knee-decision-core.test.mjs` 已覆盖：

- 动作同义词归并；
- 主诉与同动作检查合并；
- 复合功能与单关节活动保持独立；
- 一个处理影响多个问题并统一复测；
- 处理区域去重；
- 无新处理时复用结果；
- 有新处理时重新测；
- 力量转训练；
- 肿胀延后复查；
- 关节处理权限和被动受限条件。
- 处理后复测仍被动受限才开放关节松动；
- 完成复测后旧处理退出当前步骤；
- 主诉改善、独立活动问题仍存在时分别更新状态；
- 主诉只在其余处理结束后统一复测一次；
- 膝后与小腿上端处理区域去重；
- 动作或位置说不清时只追加一项检查；
- 局部证据不足时不自动猜测处理；
- 力量和髋—膝控制异常生成训练入口。
- 正常方向已经检查后继续下一方向，伸屈均完成后不再重复询问；
- 屈膝位置确认没有明确结果时转入屈膝主动控制，不形成空流程。

## 5. 正式页面的数据流

```text
现有问诊与评估记录
→ knee-workflow-adapter 转换成标准事实
→ knee-decision-core 生成当前问题、当前处理和复测动作
→ 正式页面只允许当前决策单元进入即时处理队列
→ 处理记录写回单元编号与复测结果
→ 再次计算下一项
```

正式页面不再只依赖标题和标签猜测膝关节处理顺序，也不是仅给核心候选提高排序分数：旧候选即使被旧规则命中，只要不属于当前核心单元，就不能进入即时处理队列。当前单元发生变化时，处理游标回到新单元；旧处理记录中的纯复测或复查记录不会被误算成新一次处理。主动控制和力量单元直接映射到训练动作，不伪装成即时手法处理。

## 6. 第二次及以后康复

后续康复不再使用“从全部旧候选中重新排序”的流程，而是再次调用同一个膝关节决策核心：

```text
上次保留的问题与有效方向
→ 本次同条件复查及新症状确认
→ 生成本次标准事实
→ 核心只开放当前一个处理单元
→ 本次处理与复测结果写回
→ 重新计算下一项
→ 剩余控制/力量问题进入本次训练
```

- 同一处理区域在本次康复中只做一次；
- 上次康复有效的区域不会被永久禁用，本次复查仍支持时可以再次处理；
- 上次无效的旧候选不能绕过核心直接出现；
- 肿胀继续按时间复查，不占据每一轮即时处理；
- 后续训练读取本次复查后的核心决策，不沿用第一次的固定排序。
