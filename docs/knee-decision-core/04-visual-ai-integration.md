# 膝关节视觉AI接入与判断标准

> 版本：后续接入预留方案。当前产品不启用摄像头或视觉模型；视觉AI只提供测量事实，不诊断组织问题，不直接决定手法。

在视觉功能开放前，普通用户使用“膝后主动下压双侧比较 + 直腿抬高保持”完成主动伸直和控制自测；视觉模块以后作为可选辅助，不替代该路径。

## 1. 产品定位

视觉层负责：

- 判断画面是否可用；
- 识别髋、膝、踝等人体关键点；
- 计算主动膝屈伸角度和动作轨迹；
- 判断动作是否完整、重复是否稳定；
- 生成左右对比和处理前后对比；
- 把结果转换成决策核心可读取的检查事实。

决策核心负责：

- 将视觉结果与主诉位置、感觉、分数和人工检查合并；
- 建立问题清单；
- 选择后续检查、处理、复测或训练；
- 判断是否需要专业检查。

视觉模型不能直接输出“股直肌紧张”“半月板问题”或“需要关节松动”。

## 2. 技术路线

```text
浏览器摄像头或本地视频
→ MediaPipe Pose Landmarker
→ 髋/膝/踝关键点及可信度
→ 画面质量门槛
→ 角度、动作阶段和重复稳定性
→ 左右侧或同侧前后比较
→ KneeFindingFact
→ 膝关节决策核心
```

MediaPipe Pose Landmarker支持图片、视频和实时流，能够返回33个姿态关键点、归一化图像坐标和世界坐标，适合在浏览器端完成第一版测量：

- https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/PoseLandmarker
- https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/PoseLandmarkerResult
- https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/PoseLandmark

第一版不调用通用多模态大模型逐帧判断。大模型以后只用于解释结果或检查拍摄说明是否易懂，角度计算使用可重复的关键点算法。

## 3. 第一批动作协议

### 3.1 主动膝伸直

- 机位：严格侧面，摄像头高度接近膝关节；髋、膝、踝完整入镜。
- 动作：按当前评估说明完成主动伸直，连续3次，每次末端停留约1秒。
- 输出：每次最大膝角度、三次中位数、三次极差、左右差异。
- 用途：辅助判断主动伸直是否接近另一侧；普通用户路径不由视觉结果推断被动活动。

### 3.2 主动膝屈曲

- 机位：严格侧面；髋、膝、踝完整入镜。
- 动作：连续3次弯膝到当前可接受末端，不追求强压。
- 输出：每次最小膝角度、三次中位数、三次极差、左右差异。
- 用途：辅助判断屈膝范围，不能判断末端感或关节囊限制。

### 3.3 下蹲

- 侧面：测下蹲深度、膝屈曲轨迹、躯干与小腿的相对运动。
- 正面：只观察左右负重、膝盖明显向内/向外移动和动作对称性。
- 动作：连续3次，使用相同脚位和速度。
- 完整一遍：从站立开始，进入下降阶段，到达最低点，再回到接近起始站立。
- 输出：完成次数、每次最低角度、重复差异、是否中途停止。

### 3.4 下台阶

- 正面与侧面分开录制，不要求用户同时满足两个机位。
- 动作：支撑脚站在固定高度台阶，另一脚脚跟轻点地后返回，连续3次。
- 完整一遍：开始稳定站立—下降—触地或到达约定最低点—返回起始位置。
- 输出：完成次数、支撑膝屈曲、明显的膝内移趋势、骨盆/躯干代偿和重复稳定性。
- 下台阶与下楼梯归入同一个标准功能动作。

## 4. 画面质量门槛

以下数值是首轮产品工程门槛，不是医学诊断标准；必须用真实拍摄继续校准。

| 项目 | 首轮标准 | 不满足时 |
| --- | --- | --- |
| 髋、膝、踝关键点置信度 | 每点至少0.75 | 该帧不参与计算 |
| 可用帧比例 | 至少85% | 整段无效，提示重新拍摄 |
| 最少有效帧 | 12帧 | 整段无效 |
| 机位 | 用户确认正面或侧面；拍摄中保持不动 | 不输出角度比较 |
| 入镜范围 | 对应动作需要的关键点完整入镜 | 提示后退或调整摄像头 |
| 光线与遮挡 | 人体轮廓清楚，膝部不被家具或他人遮挡 | 重新拍摄 |
| 重复稳定性 | 3次峰值极差不超过5° | 标记“需要再做一组” |

系统必须允许输出“本次无法判断”，不能在画面不合格时强行生成正常或受限结果。

## 5. 按关节、方向和测试方法分别判断

膝角度使用髋—膝—踝三个关键点计算：完全伸直接近180°，屈曲时角度减小。

不能把同一组角度门槛推广到踝、髋、肩或其他关节。正式判断必须结合测试方法对应的测量误差、当前关节方向的活动幅度、本次重复稳定性以及同一用户的基线。缺少可靠单摄像头验证时，只显示数值和趋势，不自动生成“受限”。

### 5.1 膝关节侧面主动屈伸试验门槛

| 三次中位数差异 | 产品输出 | 决策用途 |
| --- | --- | --- |
| 0～5° | 本次两侧接近 | 可记录为视觉结果接近，但仍保留用户的不适信息 |
| 大于5°、小于10° | 可能存在差异 | 再做一组；不生成活动受限处理 |
| ≥10°且两侧重复稳定 | 明显差异 | 生成“主动范围比另一侧小”的检查事实 |

### 5.2 膝关节处理前后比较

- 必须使用同一机位、同一动作、同一侧和相近速度；
- 两次画面都必须通过质量门槛；
- 同次康复首轮暂以角度变化≥10°作为“视觉上明显变化”的工程阈值；
- 小于10°只记录数值，不单独判定处理有效；
- 疼痛分数下降仍可单独证明症状方向有效；
- 视觉范围改善但疼痛变重时，不判为整体改善。

这些膝关节阈值优先用于同一用户、同一设备、同一机位的相对比较，不作为人群正常值，也不用于踝关节。现有研究显示单摄像头在受控膝屈伸任务中具有应用潜力，但误差会随任务和角度变化，不能假设固定偏差：

- https://pmc.ncbi.nlm.nih.gov/articles/PMC10164488/
- https://pubmed.ncbi.nlm.nih.gov/39897097/
- https://preprints.jmir.org/preprint/102399

### 5.3 踝关节不得照搬膝关节门槛

| 踝足方向/任务 | 第一版测量方式 | 判断标准 |
| --- | --- | --- |
| 负重背屈 | 膝碰墙距离为主；侧面小腿倾角为辅助 | 距离变化约1.6～1.9cm或角度变化约4.6～4.7°才更可能超过测试误差；产品首轮用约2cm作为明显变化参考 |
| 非负重背屈 | 左右主动动作对比 | 只显示相对趋势；完成独立验证前不套用膝关节5°/10°门槛 |
| 跖屈 | 侧面主动动作 | 先做同侧前后趋势，不根据单次角度自动判断异常 |
| 内翻/外翻 | 人工左右观察和用户反馈 | 单摄像头关键点不足以稳定反映细小足踝运动，第一版不生成绝对角度结论 |
| 提踵 | 完成次数、脚跟高度和重复稳定性 | 判断功能完成度，不当作踝活动度角度 |

负重弓步测试的系统综述报告，最小可检测变化平均约为4.6～4.7°或1.6～1.9cm。因此踝背屈更适合采用该测试自身的单位和误差，而不是套用膝角度阈值：

- https://pubmed.ncbi.nlm.nih.gov/25704110/

### 5.4 后续所有关节的阈值结构

每个视觉协议必须单独配置：

```text
关节 + 方向 + 主动/被动 + 负重/非负重 + 机位
→ 测量单位（度、厘米、次数或轨迹）
→ 允许误差
→ 需要重测的区间
→ 明显差异门槛
→ 是否允许自动生成异常事实
```

视觉模块目前只实现膝关节侧面屈伸。踝足模块完成独立验证和配置后才能开放。

## 6. 动作完成度判断

### 6.1 可自动判断

- 是否形成完整的开始—下降/弯曲—返回轨迹；
- 是否完成约定次数；
- 是否在中途停止；
- 三次动作深度是否接近；
- 是否出现明显左右负重偏移；
- 是否出现明显的膝内移趋势。

### 6.2 不能自动推断

- 因为疼痛、害怕、无力还是不理解动作而停下；
- 肌肉是否紧张；
- 关节末端感；
- 韧带、半月板或其他结构状态；
- 细小的胫骨旋转和真实三维膝外翻角度。

正面单摄像头对动态膝外翻的绝对角度误差可能很大，因此第一版只显示“膝盖出现明显向内移动”，不显示诊断性外翻角度，也不用于预测损伤风险：

- https://pmc.ncbi.nlm.nih.gov/articles/PMC11399566/

## 7. 与用户反馈合并

每个视觉动作完成后只追问必要内容：

1. 刚才有没有出现不适；
2. 有不适时，在人体图上选择位置；
3. 选择感觉性质；
4. 如果是原本困扰的症状，选择0～10分；
5. 如果中途停止，选择疼痛、无力/不稳、担心继续或动作没看懂。

视觉结果与用户反馈分开保存。例如：

```text
视觉：右膝伸直比左侧少12°，重复稳定
用户：伸直末端内侧酸痛4/10
决策事实：右膝主动伸直范围偏小，并出现熟悉的内侧酸痛
```

## 8. 决策核心调用

| 视觉输出 | 转换结果 | 后续行为 |
| --- | --- | --- |
| 画面无效 | `unknown` | 调整机位后重拍或改成人工选择 |
| 两侧接近 | `normal` | 不生成活动受限处理；不清除疼痛问题 |
| 可能有差异 | `unknown` | 再做一组，不进入处理 |
| 明显差异 | `limited` | 建立主动活动受限问题 |
| 中途停止 | 单独记录未完成 | 询问停止原因后决定路径 |
| 动作完整但明显不稳 | `function-control` | 转入动作控制检查或训练 |

普通用户的视觉检查只生成主动活动结果。专业人员可以另外输入人工完成的被动范围，视觉AI不自动把主动受限解释为关节受限。

## 9. 数据与隐私

- 第一版在浏览器本地处理；
- 默认只保存角度、置信度、动作次数、结果和时间，不保存原视频；
- 用户主动选择时才保存或上传视频供专业人员复核；
- 视频上传功能与视觉测量核心分开实现。

## 10. 实施顺序

1. 完成侧面主动伸直和屈曲；
2. 用10～20名内部测试者验证机位、稳定性和左右比较；
3. 加入侧面下蹲；
4. 加入正面下蹲和下台阶的动作完成度；
5. 由康复人员对比人工角度与视觉结果，重新确定5°/10°门槛；
6. 验证稳定后再接入公开流程。
