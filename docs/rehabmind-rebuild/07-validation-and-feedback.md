# 07 验证与反馈体系

## 1. 当前测试为什么不够

源码中出现某个词、某条规则或某张卡片，不代表真实用户路径合理。新验收必须验证完整语义链：

```text
给定原始描述和后续选择
→ 系统建立了哪些问题
→ 为什么选择这些检查
→ 检查结果生成了哪些候选
→ 处理后复测了什么
→ 哪些方向被保留或排除
→ 训练是否只来自实际差距
```

## 2. 三层测试

### 数据层

- 原始病例是否可追溯；
- 未记录信息是否保持未知；
- 关系是否记录有效、无效和未复测；
- 同名区域、动作和训练是否正确归一。

### 决策层

使用纯数据测试，不依赖页面：

- 多部位是否同时保留；
- 不知道是否继续；
- 已处理区域是否去重；
- 主诉改善后其他问题是否保留；
- 训练是否来自 findings 和目标；
- 没有依据时是否拒绝凑数。

### 页面端到端

自动点击真实流程，断言用户实际看到的检查、处理、复测、训练和总结。不能只使用源码字符串匹配代替端到端测试。

## 3. 首批金标准病例

从线下记录中选择并由康复师审核，至少包括：

- 下楼膝内侧不适；
- 下蹲膝前不适；
- 膝伸直受限；
- 急性外踝扭伤伴肿胀；
- 踝背屈受限；
- 小腿外侧不适；
- 足底或足跟不适；
- 崴脚后同时出现膝和踝问题；
- 用户只描述受伤经过；
- 用户说不清位置或没有固定动作；
- 多次选择不知道；
- 双侧但一侧更重；
- 主诉改善但活动度仍未达到健侧；
- 所有处理后主诉仍未到 0 分；
- 第二次康复仍有肿胀、活动受限和力量不足。

这些病例用于验证，不写成固定产品入口。

## 4. 每条路径的验收问题

### 信息收集

- 是否错误把受伤经过当成当前主诉动作；
- 是否要求用户判断组织名称；
- 是否重复询问原文已经包含的信息；
- 是否允许多位置和不知道；
- 首轮问题是否控制在必要范围。

### 评估

- 是否只选择与当前问题相关的检查；
- 是否出现明显无关的足趾或其他关节检查；
- 动作说明是否普通人能看懂；
- 因疼痛不能完成是否同时记录不适；
- 同一动作是否重复检查。

### 处理复测

- 是否优先主诉最相关方向；
- 是否明确展示本轮主要目标，而没有把配合区域写成同等重要；
- 直接定位证据是否正确归入主要目标；
- 完全没有主次依据时是否保持组合结果，没有虚构主因；
- 是否重复处理同一肌肉区域；
- 一组处理后是否同时复测相关异常；
- 是否错误要求肿胀、力量立即变化；
- 有改善但未达到健侧时是否继续；
- 主诉未到 0 分时是否保留有效方向。

### 训练

- 是否包含无依据的补位动作；
- 是否覆盖检查出的局部力量与控制差距；
- 是否进入骨盆稳定、髋膝踝联动和实际功能；
- 难度是否符合当前阶段；
- 第一组反馈是否能够调整组数、个数和版本。

## 5. 用户反馈内容

试用时只收集有助于修改产品的问题：

- 哪一步不知道要做什么；
- 哪个问题不知道怎么选；
- 哪项检查太专业或无法完成；
- 哪个处理看不懂或感觉重复；
- 系统是否遗漏了真正想解决的问题；
- 哪个训练与自身情况无关；
- 整体完成时间和中途退出位置；
- 第二次使用时是否容易找到上次记录。

## 6. 量化指标

- 首轮补充信息的中位题数；
- 选择“不知道”的字段分布；
- 评估中无法完成和退出的比例；
- 重复检查或处理出现次数，目标为 0；
- 无来源训练出现次数，目标为 0；
- 每条方案的来源覆盖率；
- 完成率和中途退出阶段；
- 用户是否能准确说出“这次主要解决了什么”。

## 7. 反馈闭环

每条反馈进入以下流程：

```text
用户反馈
→ 判断是解析、知识、决策还是界面问题
→ 建立可复现用例
→ 修改对应单一来源文档或规则
→ 增加自动化回归
→ 临床审核
→ 再发布
```

不能只修改页面文案掩盖底层决策错误。
