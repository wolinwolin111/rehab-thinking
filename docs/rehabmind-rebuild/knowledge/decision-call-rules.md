# 产品调用、冲突与未知规则

## 1. 关系库不是问卷

关系中的字段只供决策引擎判断。用户每次只看到当前下一步需要完成的一个问题、一个检查或一组处理。

一条关系只有在以下条件同时满足时才进入候选：

1. 当前优先问题与触发位置、性质或任务相符；
2. 必要安全信息已经获得，或未知并不阻止低风险下一步；
3. 本次尚未尝试同一主要目标；
4. 有一个用户能够完成的确认方法；
5. 有明确复测对象；
6. 关系已通过临床审核并符合用户身份权限。

## 2. 每一步只选择一个下一步

候选排序优先考虑：

1. 会改变安全路径的信息；
2. 当前主诉的直接症状调整；
3. 与多个未解决问题共同相关的主要目标；
4. 已有检查支持、且尚未尝试的目标；
5. 其他独立能力问题。

界面不显示候选列表、证据等级、匹配分数和开发者解释，只显示用户现在要做的事。

## 3. 不知道不会直接终止

用户选择“不知道”时：

- 能用一个简单动作确认：换成通俗动作；
- 只影响候选排序：保存未知，继续下一个有价值步骤；
- 需要专业触诊、被动检查或工具：普通用户跳过该检查，转低风险主动路径；
- 关系到安全：保存记录，并明确需要补充的医学信息；
- 多个候选都无法确认：回到症状管理、可完成的功能训练或专业评估建议，不能显示空方案。

## 4. 主要目标与配合处理的调用

处理卡片只突出：

```text
部位：主要目标
执行：本轮要做的处理
```

配合处理最多保留 1～2 项，并且必须服务于同一个主诉或动作。它们不在总结中分别显示“有效”。

处理后：

- 主要目标有直接定位证据且复测改善 → `primary-supported`；
- 主要目标明确但整组后才改善 → `primary-hypothesis`；
- 完全无主次 → `group-only`；
- 结果矛盾或无法复测 → `uncertain`。

## 5. 去重与复测

### 处理去重

一次康复中使用以下去重键：

```text
目标类型 + 标准区域/关节 + 方向 + 侧别
```

同一主要区域已经处理过，再被其他问题命中时，显示“前面已处理，直接复测这个动作”，不重复处理。

### 复测去重

每组处理结束后，只生成：

- 当前主诉动作；
- 处理前异常且与本轮直接相关的 1～2 项动作。

同一个标准动作承载多个问题时只做一次。例如同一次伸膝可同时更新范围、内侧疼痛和刮擦感。主诉动作与完全相同的活动方向共用结果并一起完成；下楼、下蹲等复合任务仍保留独立功能状态。

### 结果推进

- 分数下降或范围改善：方向有效，但不要求到 0 分；
- 有改善但仍未达到健侧：保存有效方向，继续其他未重复候选；
- 到 0 分且同方向范围达到目标：该标准动作当前完成；
- 无变化：降低优先级，换下一候选；
- 变差：停止该方向，降低刺激或回到评估；
- 所有候选结束仍未完全恢复：把所有有效方向转为居家和下次重点，同时保留未解决问题。

## 6. 冲突处理

### 病例之间冲突

如果相似触发在不同病例中指向不同主要目标：

- 不删除任何一条；
- 找出能区分它们的检查或症状调整；
- 缺少区分方法时降低两条关系的产品优先级；
- 不把频次最高的目标直接写成确定原因。

### 同一病例内冲突

- 前后反应不一致：保存日期、阶段和当时诱发条件；
- 同一动作有多个症状：分别更新各表现；
- 主诉改善但活动仍差：主诉状态改善，活动问题继续；
- 活动改善但功能仍差：继续功能与训练阶段。

## 7. 权限规则

| 内容 | 普通用户 | 教练 | 专业人员 |
| --- | --- | --- | --- |
| 主动动作、症状评分、低风险控制 | 显示 | 显示 | 显示 |
| 自我轻柔放松 | 适配后显示 | 显示 | 显示 |
| 被动活动与末端判断 | 不要求 | 适配/建议协助 | 显示 |
| 关节松动 | 不显示自助手法 | 仅显示建议线下处理 | 显示审核后的专业内容 |
| 神经手法、术后专项 | 不显示 | 不显示或转专业 | 受审核和限制信息控制 |

## 8. 发布门槛

关系进入正式产品必须满足：

- `status = clinical-reviewed`；
- 来源能回到原始记录；
- 触发、排除、复测和未知处理完整；
- 没有把治疗者解释写成诊断；
- 普通用户版本已完成安全降级；
- 至少通过一个正向、一个未知、一个不匹配测试用例。

`draft` 关系只能在内部审核页出现，不能控制公开路径。
