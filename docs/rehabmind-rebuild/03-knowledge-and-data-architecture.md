# 03 知识与数据结构

## 1. 总体结构

新结构不再使用“关节内容数组 + 标签匹配”作为主干，而是由六类对象组成：

```text
一次康复记录 CaseSession
├─ 原始描述 RawNarrative
├─ 症状位置 SymptomSite（可多个）
├─ 功能任务 FunctionalTask（可为空或多个）
├─ 问题 Issue（已确认/待确认/跟踪）
├─ 证据 Evidence（检查与反馈）
├─ 候选因素 CandidateFactor
├─ 处理实验 InterventionTrial
└─ 训练与后续计划 ExercisePlan / FollowUpPlan
```

关节、肌肉、局部组织和功能动作以知识模块形式被这些对象调用。

## 2. 症状位置模型

### 位置层级

位置采用层级结构，不要求用户说出组织名称：

```text
下肢
├─ 大腿
│  ├─ 前侧 / 后侧 / 内侧 / 外侧
│  └─ 上段 / 中段 / 下段
├─ 膝周围
│  ├─ 前 / 后 / 内 / 外
│  └─ 髌骨周围 / 关节线附近 / 鹅足附近等可选细分
├─ 小腿
│  ├─ 前侧 / 后侧 / 内侧 / 外侧
│  └─ 上段 / 中段 / 下段
├─ 踝周围
│  ├─ 前 / 后 / 内踝 / 外踝
└─ 足
   ├─ 足跟 / 足底 / 足弓 / 前脚掌
   ├─ 脚背 / 足内侧 / 足外侧
   └─ 足趾
```

每个位置对象保存：

- 用户原话；
- 左、右、双侧或未知；
- 大区域和可选细分；
- 症状性质；
- 是否肿胀、按压不适或感觉变化；
- 相关动作；
- 信息可信度。

### 不从位置直接诊断

“小腿外侧”只用于调用局部软组织、踝内外翻控制、步态和相邻关节模块，不能直接生成“腓骨肌问题”。

## 3. 功能任务模型

功能任务与症状位置分开保存：

- 受伤发生动作；
- 当前诱发动作；
- 用户想恢复的功能；
- 评估检查动作；
- 处理后复测动作。

系统必须确认某个动作是“现在仍会出现问题”，才能把它作为主诉复测动作。只描述受伤经过时不能自动转成复测目标。

同一动作只建立一个标准任务对象。例如“弯腰”和“腰部前屈”在动作层可以归一，但复合任务如“下楼”不能简单等同于单一膝屈曲。

## 4. 功能模块

首批模块包括：

### 局部症状模块

- 肿胀和淤青；
- 局部按压不适；
- 酸、胀、牵扯、刺、卡挤；
- 麻、电、放射或感觉变化；
- 无力、不稳或打软；
- 无固定诱发动作。

### 关节能力模块

- 膝伸直、膝屈曲；
- 踝背屈、跖屈、内翻、外翻；
- 必要的髋部活动与骨盆稳定；
- 普通用户主动活动；
- 专业模式主动与被动分开。

### 肌肉与控制模块

- 肌肉紧张位置比较；
- 相关方向的发力表现；
- 同功能肌与拮抗方向；
- 局部力量、稳定和动作控制；
- 肌肉区域去重，不重复列长串肌肉。

### 功能动作模块

- 走路与承重；
- 下蹲与坐站；
- 上下台阶；
- 提踵；
- 单腿站；
- 跑步、落地、减速和变向按目标逐级开放。

## 5. 问题状态

每个问题必须使用明确状态：

- `suspected`：根据主诉生成，尚未检查；
- `confirmed`：检查支持；
- `not_found`：本次检查未发现；
- `unknown`：用户不知道或无法判断；
- `not_testable_now`：肿胀、疼痛或环境原因暂不适合；
- `in_treatment`：当前正在处理；
- `improved`：本次出现改善；
- `resolved_for_now`：当前达到目标或与健侧接近；
- `unchanged`：本次没有变化；
- `worse`：变差；
- `training`：移交训练；
- `medical_followup`：需要补充医学信息；
- `carry_forward`：带到下一次康复。

未知不是阴性，改善也不等于完全解决。

## 6. 候选因素与证据

候选因素不能只保存一个分数，应保存支持与反对证据：

```text
候选因素：小腿后侧张力可能影响踝背屈
支持：背屈受限、小腿后侧比另一侧紧
反对：轻柔松解后背屈和主诉均无变化
未知：被动活动未检查
来源：病例 R023/R061 + 解剖审核 A014
```

候选优先级由以下信息共同决定：

- 与当前优先主诉的距离和动作相关性；
- 检查结果；
- 症状性质和发生阶段；
- 线下病例中的出现与反应记录；
- 是否已经尝试；
- 用户身份和安全边界。

## 7. 处理去重图

同一个处理区域只执行一次，并记录它可能影响的全部问题：

```text
处理：小腿后侧区域
可能影响：踝背屈、跖屈末端、提踵、走路推进
完成后复测：本次原来异常且与该区域相关的项目
```

后续另一个问题再次命中该区域时，系统显示“前面已经处理过，直接复测这个动作”，不能重新安排同样处理。

### 处理主次关系

一组处理需要区分：

```text
主要处理目标
├─ 选择依据：按压、屏蔽、发力、拉伸、动作调整或康复师明确判断
├─ 配合处理：与主要目标相关、用于改善整体张力或动作环境的区域
└─ 复测：主诉 + 本轮原有异常
```

如果主要目标有直接的症状调整证据，整组处理后的改善优先记入主要方向；配合区域只记为参与处理，不分别生成有效结论。只有原资料完全没有说明主次时，才保留为“组合方向有效，主要因素待确认”。

## 8. 来源与版本

所有检查、处理、训练和关系对象必须具备：

- `sourceIds`；
- `evidenceType`：线下病例、用户确认规则、解剖资料、指南或试验假设；
- `reviewedBy`；
- `reviewStatus`；
- `version`；
- `lastUpdated`。

这样才能回答用户最关心的问题：这条内容到底有没有使用线下资料，以及资料在决策中的哪个环节发挥作用。
