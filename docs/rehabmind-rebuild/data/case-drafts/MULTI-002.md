## 2. 问题演进

| 阶段 | 明确主诉或发现 |
| --- | --- |
| 初期 | 右踝多方向活动受限 |
| 第三次 | 打球后膝盖有点不适 |
| 第四次 | 跑步后右跟腱不适，持续一到两天 |
| 第五次 | 右膝绷直到末端不适；走两三公里后膝不适；特定站立发力出现足趾背麻和牵扯 |
| 第六次 | 打球后膝下缘痛；膝绷直不适；屈髋时膝扭感 |
| 后期 | 右侧屈伸髋能力差，屈髋和蹦跳时出现代偿 |

问题从踝逐渐扩展到膝、髋和步态，不能在初诊时预先生成完整髋膝踝方案，也不能在后期继续只处理踝。

## 3. 高价值反应实验

### 屈髋时膝扭感

- 第六次：做屈髋时膝盖有扭感；
- 手动把骨盆往后旋后，动作恢复正常；
- 本轮主要目标可记录为“髋/骨盆动作控制”，定位依据是动作调整后主诉立即变化；
- 这是 `primary-supported` 反应，支持把髋/骨盆控制列为主要候选因素；
- 不能据此把固定“骨盆卡旋前”作为所有同类用户的原因。

### 膝绷直不适 

- 第六次：松解外侧链和处理腓骨后，绷直膝盖正常；
- 原文没有说明外侧链和腓骨哪一个是主要目标，也没有分别复测，因此本项记录为 `group-only`；
- 后续产品应把两者作为同组候选，不能同时生成两个已验证有效标签；若临床审核能补充当时主次，再升级记录。

## 4. 步态与功能

原文连续记录：

- 走路时骨盆上下起伏；
- 摆动相启动时没有完全放松；
- 对侧承重不足；
- 右侧屈伸髋功能差导致支撑不足；
- 先练屈伸髋和支撑，再继续步态练习。

这支持训练引擎使用“功能差距 → 基础能力 → 再回到功能”的顺序。

## 5. 训练进阶事实

```text
呼吸臀桥
→ 臀桥加高度、提踵
→ 股内侧肌激活、抗阻伸膝
→ 小腿离心和步态
→ 分腿屈髋、屈伸髋功能
→ 蚌式开合处理膝内扣相关控制
```

原文还明确记录“屈髋找不到感觉，不练”，说明系统必须允许训练不适合时退出或降阶，不能要求用户完成预定动作。

## 6. 对新引擎的直接要求

- 新症状出现时建立新问题，不覆盖首次踝问题；
- 特定动作出现麻或牵扯时，保存动作、位置和条件，不把“受伤经过”混进主诉；
- 处理后先复测原主诉动作，再看相关活动；
- 明确有主要目标时保留主次；只有完全没有主次或定位依据时才记录组合有效；
- 髋膝踝联动由功能检查和反应触发，不作为所有膝踝病例的固定套装；
- 训练选择需要根据当前阶段变化，且支持“不会做/找不到感觉”的降阶。

## 7. 边界和未知

- 首次受伤机制、影像和康复目标未记录；
- 麻和牵扯只在特定发力组合出现，原文没有完整感觉分布检查；
- 专业神经和关节手法不进入普通用户自助候选；
- 手法执行反思是专业内容质量来源，不是普通用户操作说明。
