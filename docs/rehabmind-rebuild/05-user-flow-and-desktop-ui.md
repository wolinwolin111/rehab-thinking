# 05 用户流程与桌面界面

## 1. 设计目标

界面不展示系统拥有多少规则，只展示用户当前需要完成的事情。

每个页面都应让用户一眼看懂：

- 当前在解决什么；
- 现在做什么；
- 怎么做；
- 需要选择或记录什么；
- 完成后去哪里。

避免重复解释“为什么这样设计”、内部标签、评分算法和候选排序。

## 2. 页面总体结构

桌面端使用三个稳定区域：

1. 顶部：问题清单和当前流程阶段；
2. 中间：当前唯一任务；
3. 右侧：已确认的信息、发现的问题和历史记录。

顶部问题清单按状态排序：

- 当前处理：最前、最醒目；
- 待确认或未处理：次级样式；
- 已改善或当前完成：弱化样式；
- 等待医学信息：独立状态。

不在页面中同时展开所有问题详情。

## 3. 症状信息收集

### 首屏

首屏提供：

- 一个自由描述输入框；
- 一句规范提示：说明发生经过、现在位置和当前会出现的情况；
- 一个简短示例；
- “不知道怎么描述”时使用身体区域和简短选项的入口。

### 身体位置

允许：

- 直接点击人体图上的细分区域；
- 系统根据点击区域自动记录左右、正背面、大区域和具体位置；
- 增加第二、第三个位置；
- 使用“大腿外侧、小腿后侧、脚背、足底”等普通人能理解的名称；
- 再次点击取消或从已识别位置中删除。

所有问答统一使用“选好后点下一步”的交互：点击选项只改变当前答案，页面不自动跳题；不再出现“确认这些选项”“确认这些位置”等第二层确认按钮。返回上一步时保留原答案，即使不修改也能直接再次进入下一题。

“上一步”和“下一步”组成固定的高对比导航条，滚动查看人体图或较长选项时仍保持可见。下一步只有当前题缺少必要答案时禁用。

右侧只展示已经确认的信息和当前正在补充的一项，不把所有未回答问题同时展开。顶部在问题较多时不显示倒计时式总数，只提示“只补充最关键的信息”。

人体图不再采用“大区域点击后再选文字部位”的两层流程，也不显示“膝盖的哪个位置”等选项。用户点击膝内侧关节线、外踝前外侧等细分区域后，系统直接建立位置记录。

主诉位置、肿胀或淤青位置、按压痛位置和感觉变化位置共用同一套细分人体图，但分别保存为不同字段。文字解析只负责预先标亮可能的位置，用户可以直接修改；说不清时可以跳过，不强迫填写自由文本。原描述只识别到“膝、腿、脚”等大区域时，不得与用户后来点击的细分位置产生“描述不一致”冲突。

用户在左右两侧都标记位置时，后续标题和操作说明统一使用“两侧、左右比较、较明显的一侧”等表述，不再出现“患侧、健侧”。

桌面端采用“左侧人体定位＋右侧局部图谱”：人体图用于确定侧别和大区域；右侧的大腿、膝盖、小腿、脚踝或足部高清皮肤图用于点击细分区域。足部局部图必须同时提供足背和足底。

用户不选择肌肉、韧带或关节组织名称。

### 动态补充

系统先自动填入解析结果，再只补充缺失且会改变路径的信息。每次一题，并支持：

- 返回上一题；
- 修改已收集字段；
- 选择不知道；
- 保存稍后继续。

任何会改变部位、侧别、机制、症状性质或主诉动作的修改，都必须使对应下游结果失效并提示需要重新确认，不能保留旧侧别或旧问题的数据。

评分按条件出现，不占用固定问卷步骤：只有用户能说清当前症状，并且存在明确静息情境或可重复动作时才显示。用户说不清、没有固定症状或当前无法重复时，直接跳过；页面不显示空评分、“待评分”或默认分数。后续检查找到可重复症状时，再在对应动作下建立基线。

## 4. 阶段过渡页

四个阶段使用简短过渡页：

- 症状信息收集完成，接下来开始评估检查；
- 评估检查完成，接下来进行针对性处理和复测；
- 处理复测完成，接下来进行训练；
- 训练结束，本次康复完成，接下来查看总结。

过渡页只说明接下来做什么，不堆积免责和解释。

## 5. 评估检查页

每次只显示一个检查。卡片结构：

```text
[检查部位]
[要做的动作]

怎么做
结果选项
```

动作名称采用“通俗描述 + 必要专业名称”，例如：

- 脚背向上勾（踝背屈）；
- 把膝盖主动绷直（膝伸直）；
- 脚掌向外转（踝外翻）。

活动范围和不适感分开询问。已知该动作原本不适时，复测不再问“是否不舒服”，直接选择新分数。

普通用户常用结果：

- 两边差不多；
- 这一侧明显更小或更弱；
- 动作会不舒服；
- 因为疼痛无法完成；
- 不知道。

“因为疼痛无法完成”同时记录该动作会疼，不能只记为未完成。

## 6. 评估完成页

不展示所有正常结果，也不逐条解释原因。只展示发现的问题：

- 主诉问题；
- 活动受限；
- 发力不适；
- 力量或控制不足；
- 肿胀、按压不适等需要跟踪的问题；
- 需要补充医学信息的问题。

问题同时进入顶部问题清单和右侧记录区。

## 7. 针对性处理页

标题拆成两个视觉层级：

```text
[部位] 小腿后侧
[执行] 轻柔肌肉松解
```

一组处理有主次时，页面突出主要目标，配合区域弱化显示：

```text
主要处理：胫骨后肌
配合处理：小腿后侧相关紧张区域
```

用户不需要逐个确认配合区域，也不为每个配合处理分别弹出复测。

正文只保留：

- 实际做什么；
- 最少必要的做法；
- 明确停止条件；
- 完成按钮；
- 返回上一步。

处理流程、算法解释和“为什么选它”不显示给普通用户。

第一项高相关处理后进入合并去重的短复测：只显示主诉和处理前已经异常且与本轮直接相关的动作，不为每块肌肉分别弹出一整套复测。主诉分数下降后，后续处理不再逐项重复主诉，只保留会改变下一步的相关活动范围；本轮处理全部结束后统一复测一次主诉。

处理页顶部显示实时清单：已完成、正在做、接下来。清单必须随复测结果更新；已经达到健侧、已经处理过或被当前结果跳过的候选不得继续出现在“接下来”。

## 8. 复测页

复测页分为主指令和次级提示：

```text
主标题：再次下楼
处理前：6/10

新评分滑条
活动范围选择（需要时）

提示：尽量保持与刚才相近的动作方式
```

评分滑条每次打开处于未选择状态，但清晰显示处理前或上次分数作为参考。评分描述与滑条位置对齐：0、1～3、4～6、7～9、10。

没有处理前评分时不进入数字复测卡。系统改为复查对应活动范围、发力表现或功能动作；若这次首次出现可稳定重复的不适，再建立新的评分基线，不伪造前后分数变化。

不再额外添加“有没有改善”按钮，由新旧分数和范围结果自动判断。

复测清单采用纵向单列动作卡，而不是一行放两张：每张卡占满可用宽度，只对应一个去重后的身体动作，顶部显示“动作序号、专业动作名称、待记录/已记录”，卡内固定分为“活动范围”和“动作不适/不适评分”两块。活动范围、力量或控制仍由后台分别保存，但同一动作只让用户操作一次；这样滑条、范围选项和状态在桌面端也不会被压缩成难以阅读的小卡。

症状性质为刺痛，或伴随表现中明确选择了按压痛/按压时，症状收集页追加“轻按反应”。用户在最不舒服的位置轻按一次，选择“清楚的刺痛、钝痛或酸胀、没有明显感觉、没有尝试”；已选择按压痛后再修改疼痛性质，不能清空这条记录。专业模式在同一结构化区显示同一字段，避免两种模式把同一证据记录成不同内容。

专业模式的部位图采用“总览图选侧别和大部位 + 单张大图切换正面/背面/内侧/外侧”的工作台。肿胀、按压痛和麻电范围分别保留自己的标签页和数据，不在同一屏并排压缩多张图。

## 9. 训练页

训练页只显示本次有依据的动作。每张卡包含：

- 动作名称；
- 起始姿势；
- 做法；
- 组数和个数；
- 第一组反馈；
- 做不了时怎样降低；
- 轻松时怎样进阶。

动作演示位置先保留占位，后续支持自行拍摄上传，不在首批依赖外部视频链接。

## 10. 本次康复总结

固定分成五块：

1. 本次排查出的问题；
2. 本次做过的处理；
3. 哪些处理有效、无效或无法判断；
4. 居家训练与阶段管理；
5. 下次重点关注。

“本次做过的处理”不能一行平铺。每项分层展示：

```text
针对：踝背屈受限、走路不适
处理：小腿后侧轻柔松解
反馈：走路 6→4 分，背屈仍小于另一侧
后续：保留居家放松，继续主动控制
```

## 11. 后续康复界面

第二次和第三次与第一次使用相同的页面骨架和阶段名称，不另设“要改善的问题”总表：

- 症状信息确认：显示上次的位置、性质和主诉动作，只询问有没有变化；
- 评估检查：逐项复查仍未解决的具体动作；
- 针对性处理与复测：只显示今天实际要做的处理；
- 训练：根据本次结果保持、降低或进阶；
- 本次总结：展示与上次相比的变化。

历史记录按次数独立保存，不覆盖第一次；界面默认折叠旧详情，按需展开。

同一个身体动作只显示一次。活动范围、动作不适、发力表现放在同一张卡片中分行回答，避免“膝盖绷直角度”和“膝盖绷直力量”分成两张近似卡片。后台仍分别记录这些结果。

## 12. 题量与中断标准

- 首轮症状补充一般 3～5 项；
- 每次只显示一个问题或动作；
- 正常结果不继续追问细节；
- 只有异常结果才追问位置、阶段、性质或分数；
- 功能动作结果使用“能完成且稳定、能完成但晃动或借力、能完成但出现熟悉不适、因不适做不完、看不出来或暂不做”，避免“动作异常”等需要专业判断的选项；
- 肌肉轻按检查必须先写清具体按压区域和左右比较顺序，并说明只按肌肉、不按骨点或关节缝；
- 同一信息只收集一次，后续复用；
- 给出清晰进度和“保存稍后继续”；
- 若信息已经足够支持下一步，立即停止继续问卷。
