## 3. 测试通过不代表什么

现有测试主要证明：

- 页面可以服务端渲染；
- 源码中存在六步流程、九区域内容、评分历史和部分规则；
- 若干保护逻辑的代码片段仍然存在。

它没有充分证明：

- 某个真实主诉最终得到的评估队列是否合理；
- 多部位是否能被同时保留；
- 用户多次选择“不知道”后是否仍有自然路径；
- 处理和复测是否真正调用了线下资料的先后关系；
- 训练是否来自当前实际能力差距；
- 页面是否让用户知道下一步要做什么。

因此后续不能以“6 项测试通过”作为临床或体验验收结论。

## 4. 当前架构基线

当前核心结构仍然是：

```text
自由输入
→ 关键词和词表解析
→ 选择一个区域
→ 固定数量评估项
→ 标签/文本相关性排序处理候选
→ 固定阶段处理与复测
→ 按标签排序并补足训练
```

当前已知根本问题：

- 线下资料被压成标签和文案，临床关系丢失；
- 区域入口仍以单一关节为主；
- 检查队列使用固定预算和截断；
- 候选排序依赖字符串匹配；
- 训练存在补足固定数量的行为；
- 不确定信息可能导致分支消失；
- 流程状态比用户当前问题更突出。
