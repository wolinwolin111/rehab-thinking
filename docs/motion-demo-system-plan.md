# RehabMind 动作演示系统完整方案

## 1. 系统目标

动作演示系统不是独立的视频库，而是康复决策流程的一部分。它需要回答五件事：

1. 现在做什么。
2. 怎么做。
3. 做的时候观察什么。
4. 什么结果说明这个方向值得保留。
5. 无变化或加重时下一步怎么调整。

系统面向正在学习运动康复或希望拓展康复业务的健身、普拉提、瑜伽等教练。内容不能默认用户已经掌握专业触诊、特殊测试和关节松动，也不能把单个动作包装成治疗某种疾病的方法。

## 2. 核心原则

### 2.1 演示服务于决策

每个演示必须挂在以下流程之一：

```text
评估检查 → 记录结果
处理试验 → 重复原动作复测
训练动作 → 下次比较能力变化
```

不能只给出“动作名称 + 视频”。

### 2.2 一次只解决一件事

- 评估演示只告诉用户如何完成当前检查。
- 处理演示只展示当前候选来源的单变量试验。
- 训练演示只展示当前阶段需要的动作和剂量。
- 原因解释放在知识详情中，不占据主要操作界面。

### 2.3 三帧演示优先，真人视频补充

默认展示体积很小的三帧演示；用户需要更多细节时，再点击查看真人视频。

```text
起始位置 → 动作过程 → 终点 / 观察位置
```

这可以保证手机端加载速度，也避免每张卡片都出现一个占空间的视频播放器。

### 2.4 候选来源，不生搬硬套

线下记录中有效的方法进入候选库，但必须通过原活动方向、原疼痛动作或原功能任务进行验证：

- 改善：保留，并用主动训练巩固。
- 不变：不继续加力，换另一个候选来源。
- 加重：撤回本次变量，降低难度或返回评估。

## 3. 演示内容分级

### A 级：用户可独立完成

适用于大部分主动检查和训练：

- 关节主动活动。
- 健患侧比较。
- 踝泵、提踵、臀桥、鸟狗、墙面滑手等训练。
- 扶持下重心转移、坐站、浅蹲和低台阶。

展示内容可以完整包含动作、剂量、进退阶和常见代偿。

### B 级：需要教练或他人协助

适用于低风险的协助检查：

- Thompson、小腿挤压等需要观察两侧差异的测试。
- 部分肩关节或神经张力检查。
- 轻柔的手动位置调整复测。

必须标注：

- 谁来完成。
- 什么时候使用。
- 阳性结果看什么。
- 什么情况立即停止。
- 不熟悉动作时可以跳过。

### C 级：仅限受训者

适用于：

- 关节附属活动检查。
- 距骨、腓骨、髌骨、盂肱关节和脊柱分节检查。
- 关节松动术。
- 需要明确手法方向和等级的处理。

普通用户只看到：

```text
为什么考虑这一方向
由谁操作
做完复测什么
出现什么反应时停止
```

具体手法视频进入“受训者内容”，不能让初学者误以为照着视频用力即可。

### D 级：不提供动作演示

出现明显错位、持续远端感觉或循环异常、进行性无力、开放损伤等情况时，只展示信息保存和专业评估流程，不展示诱发测试或处理手法。

## 4. 三种演示形式

### 4.1 三帧动作图：默认形式

每个动作包含：

- 第 1 帧：起始位置。
- 第 2 帧：动作方向。
- 第 3 帧：终点与观察位置。
- 一个循环方向箭头。
- 一条最重要的观察提示。

适合：

- 主动活动度检查。
- 等长训练。
- 踝泵、提踵、重心转移。
- 肩胛控制、墙面滑手。
- 臀桥、鸟狗、坐站等路径清楚的动作。

技术形式使用 CSS、HTML 和少量关键帧，不依赖外部素材和视频播放器。

### 4.2 自有真人短视频：核心动作

用于三帧图无法完整表达的动作：

- 步态与台阶。
- 膝触墙背屈。
- 分腿蹲、髋铰链。
- 肩胛辅助上举。
- 单脚控制和后期跑跳训练。
- 需要展示手位的协助检查。

每条视频标准：

- 10～20 秒。
- 静音也能看懂。
- 固定机位和统一背景。
- 正面或侧面只选最能说明动作的角度。
- 开头直接进入起始位置。
- 不制作长篇口播。
- 画面字幕最多三条：怎么做、看什么、何时停止。

### 4.3 第三方公开视频：临时备用

只作为自有内容完成前的占位方案：

- 只嵌入允许嵌入的视频。
- 不下载、不剪辑、不重新托管普通公开视频。
- 记录来源、作者、链接、授权状态和最后检查时间。
- 第三方链接失效时自动回退到三帧演示。

## 5. 用户界面结构

### 5.1 动作卡片默认状态

手机页面只显示：

```text
[三帧演示]
动作名称
剂量
观察什么
[看真人演示]
```

“为什么做”“详细原理”和扩展知识不放在默认卡片中。

### 5.2 全屏演示层

点击真人演示后打开全屏或接近全屏的演示层：

- 视频或三帧大图。
- 动作名称。
- 当前剂量。
- 一个主要观察点。
- 常见代偿。
- 停止条件。
- 做不了 / 太轻松两个调整入口。

退出演示后回到原流程位置，不丢失评估或训练记录。

### 5.3 评估演示卡

评估卡只保留：

- 怎么做。
- 看什么。
- 结果按钮。
- 返回上一项。

例如踝背屈：

```text
怎么做：先做健侧，再做患侧，脚跟保持接触地面。
看什么：患侧范围是否更少，是否出现刺痛或卡住。
结果：接近健侧 / 患侧更少 / 刺痛 / 卡住 / 暂不测试。
```

### 5.4 处理试验卡

```text
先记录原动作
→ 查看本次处理演示
→ 只完成一个候选处理
→ 重复原动作
→ 改善 / 不变 / 加重
```

不能用处理演示替代复测。

### 5.5 训练卡

训练卡根据当前能力提供：

- 当前版本。
- 做不了时的退阶。
- 太轻松时的进阶。
- 次日反应记录。

力量和平衡训练不要求当场变强；活动范围和疼痛动作才使用即时复测。

## 6. 动作库的数据结构

每个动作使用统一数据模型，不把文字和视频地址散落在页面代码中。

## 7. 第一批动作清单

### 7.1 踝足

评估：

- 背屈、跖屈、内翻、外翻健患侧比较。
- 扶持下重心转移。
- 四步与短距离步态。
- 坐姿/双脚提踵。
- 扶持下单脚站。
- 膝触墙背屈。
- 低台阶上步和下步。

训练：

- 踝泵和四向主动活动。
- 四方向等长与弹力带训练。
- 坐姿、双脚、偏患侧和单脚提踵。
- 脚跟到脚趾步态。
- 前后脚站、单脚站和多方向触地。

### 7.2 膝关节

评估：

- 主动伸直和脚跟滑动弯曲。
- 坐姿伸膝控制。
- 屈膝脚跟压地。
- 坐站、浅蹲、台阶。
- 髋旋转和踝背屈对比。

训练：

- 主动伸膝、股四头肌等长。
- 臀桥和单腿臀桥。
- 坐站、浅蹲和分腿蹲。
- 低台阶上步、下步和离心控制。
- 提踵和单脚控制。

### 7.3 髋、骨盆和腰背

评估：

- 腰背前屈、后伸、侧屈和旋转。
- 髋内外旋、屈髋。
- 臀桥、鸟狗和髋铰链。
- 坐站、走路和弯腰取物。

训练：

- 呼吸与骨盆控制。
- 臀桥、蚌式开合、鸟狗。
- 站立屈髋和髋铰链。
- 分腿站、单腿屈髋和负重髋铰链。

### 7.4 肩部

评估：

- 前屈、后伸、外展、水平内收、内旋和外旋。
- 墙面推和肩胛控制。
- 颈椎、胸椎和前臂旋转。
- 举手、摸后脑、手到腰后和拧毛巾。

训练：

- 肩袖内外旋等长。
- 墙面滑手。
- 肩胛后缩下沉。
- 前锯肌墙面推。
- 轻阻力斜向上举和分级过顶训练。

## 8. 内容制作流程

### 8.1 从线下记录建立选题

```text
高频评估项目
→ 高频异常结果
→ 常用处理候选
→ 常用训练巩固
→ 是否需要动作演示
```

优先制作会反复使用、动作容易被误解、或需要观察代偿的内容。

### 8.2 编写动作脚本

每个动作先写一张不超过一页的脚本：

- 使用场景。
- 起始位置。
- 三个以内的动作步骤。
- 唯一主要观察点。
- 常见代偿。
- 停止条件。
- 复测动作。

### 8.3 制作三帧版本

- 使用统一人物比例和颜色。
- 固定相机视角。
- 需要比较左右时使用镜像布局。
- 用箭头表示运动方向。
- 红色只用于停止或错误提示，不用于普通装饰。

### 8.4 拍摄真人版本

零成本设备：

- 一部手机。
- 固定支架或稳定桌面。
- 纯色墙面。
- 自然光或已有室内灯。
- 免费剪辑软件。

每次集中拍摄同一身体部位，统一服装、背景、距离和机位。

### 8.5 压缩与导出

- 主文件保留高质量原片。
- 网页版本使用 MP4/H.264。
- 竖屏建议 720×1280；横向动作可使用 960×720。
- 每条目标大小控制在约 1～4MB。
- 单独导出 WebP 封面。
- 视频默认不自动播放，点击后才加载。

### 8.6 审核与发布

每条动作至少经过：

1. 动作准确性审核。
2. 适用人群和停止条件审核。
3. 手机画面和字幕审核。
4. 版权与出镜授权审核。
5. 上线后版本记录。

## 9. 零成本技术架构

### 9.1 初期

- 三帧动画直接放在前端代码中。
- 动作说明保存在 TypeScript 或 JSON 文件中。
- 少量真人视频可放在当前站点静态资源中。
- 第三方视频仅作为备用链接。

这一阶段不需要数据库和后台管理系统。

### 9.2 动作数量增加后

推荐使用 Cloudflare R2 存放自有视频：

- 免费额度内可存放早期动作库。
- 外网流量不收费。
- 视频地址仍由动作数据文件管理。
- 前端按需加载，不进入首屏资源。

官方定价说明：<https://developers.cloudflare.com/r2/pricing/>

### 9.3 YouTube 备选

自有视频可以上传为“不公开”并嵌入网页：

- 使用 `youtube-nocookie.com` 隐私增强模式。
- 保留本地原始视频，避免以后更换平台时丢失素材。
- 不把“不公开”当成真正的隐私控制，获得链接的人仍可分享。

官方嵌入说明：<https://support.google.com/youtube/answer/171780>

### 9.4 不建议作为长期主库

- Vimeo 免费账户容量有限，适合演示，不适合完整动作库。
- GitHub Raw 不适合视频分发。
- 随机第三方康复视频可能被删除、禁止嵌入或改变内容。

## 10. 素材版权与出镜管理

### 自有拍摄

- 明确拍摄者、出镜者和产品使用范围。
- 保存出镜授权。
- 不在画面中出现患者隐私、病历或无关人员。
- 产品拥有可持续使用和修改的源文件。

### 开放授权素材

- 每个文件单独记录许可。
- CC BY需要署名。
- CC BY-SA修改后可能需要使用相同许可。
- CC BY-NC不适合作为未来商业产品的核心素材。
- 不确认许可时，不下载和重新发布。

Wikimedia Commons复用说明：<https://commons.wikimedia.org/wiki/Commons%3AReusing_content_outside_Wikimedia/en>

## 11. 产品内的加载策略

- 首屏只加载文字和封面。
- 三帧动画进入视口后才播放。
- 真人视频点击后才请求文件。
- 同一页面只允许一个视频播放。
- 关闭演示层时停止视频。
- 网络较慢时自动保留三帧版本。
- 视频加载失败时显示动作图和文字，不显示空白播放器。
- 用户可以选择“减少动画”。

## 12. 反馈和数据

早期不需要复杂数据分析，只记录有助于改进动作内容的事件：

- 是否打开真人演示。
- 是否选择“做不了”或“太轻松”。
- 哪个动作经常出现“看不懂”。
- 处理后原动作改善、不变或加重。
- 次日是否出现反弹。

不以播放次数判断临床有效性；核心指标是用户是否完成正确复测，以及动作是否帮助其选择下一步。

## 13. 分阶段上线

### 阶段一：三帧动作库

目标：覆盖当前 Demo 的基础流程。

- 完成 20 个核心动作。
- 统一动作卡数据结构。
- 统一手机全屏演示层。
- 第三方视频作为临时补充。

验收标准：不打开视频也能完成全部基础流程。

### 阶段二：自有真人视频

目标：替换最常用、最容易误解的第三方内容。

- 拍摄第一批 20～30 个动作。
- 完成统一封面、字幕和压缩。
- 接入按需加载和失败回退。
- 建立出镜授权与版本表。

验收标准：踝、膝、腰髋和肩部核心训练不依赖外部视频。

### 阶段三：评估与手法演示分层

目标：建立专业等级。

- 补充协助检查视频。
- 建立“仅受训者”内容标识。
- 将关节松动与处理演示绑定到明确进入条件和复测动作。
- 增加内容审核记录。

验收标准：用户能够明确分辨“可以自己做”“需要协助”“仅限受训者”。

### 阶段四：动作管理工具

当动作超过约100个、多人参与维护时，再建设后台：

- 搜索和筛选动作。
- 修改剂量和提示。
- 替换视频。
- 审核与版本发布。
- 查看失效外部链接。

早期不建议先开发后台，避免把时间花在尚未稳定的内容管理上。

## 14. 推荐的当前实施路线

```text
现有 CSS 动画
→ 升级为三帧标准组件
→ 建立统一动作数据文件
→ 覆盖20个核心动作
→ 用手机拍摄第一批自有视频
→ 上传R2或YouTube不公开
→ 逐步替换第三方视频
→ 再扩展协助检查与受训者手法内容
```

这条路线平台费用可以保持为零，主要投入是内容整理、拍摄和专业审核时间。它也不会因为某个第三方视频下架而让康复流程无法继续。

## 15. 最终验收标准

完整动作演示系统应达到：

- 所有核心评估和训练均有三帧演示。
- 复杂动作有自有真人视频。
- 每个动作都写明观察点和停止条件。
- 处理演示必须绑定原动作复测。
- 训练动作提供退阶和进阶。
- 手机端默认不被视频播放器占满。
- 外部视频失效时仍可完成流程。
- 所有第三方素材具有可追溯授权记录。
- “自行完成、需要协助、仅限受训者”清楚区分。
- 动作版本和专业审核状态可追踪。
