# UI 表现层整理：范围、架构与分批实施方案

> 日期：2026-09-09；规划基线：`06799fe`。
> 状态：待实施；供其他开发模型执行。本轮只创建方案，没有实施重构。
> 目标：让统一的视觉要求成为组件默认行为，减少 CSS 竞争和跨视口回退；不是重写业务系统。

3. 阅读 `patient-mobile-ui-comprehensive-remediation-2026-09-09.md`。该文档负责患者体验目标，本方案负责如何安全地将其落实为可维护代码。
4. 检查 `git status --short`、HEAD、适用的 `AGENTS.md`；保留已有工作。HEAD 不同则对照差异更新事实，不覆盖后续修复。
5. 按 P0→P6 批次实施；每批必须有退出条件与验证记录，未过门槛不能宣称整项完成。
6. 不另起全量设计改版，不安装新 UI 框架，不复制临床规则，不自动提交或推送。
7. 如果测试侧尚未接入，只能报告“开发实现完成、验收待补”，不得将已登记的测试视作已通过。

## 1. 完成后的形态

### 1.1 必须实现

- 一个组件的外观、内部排布、状态样式由一个明确所有者维护。
- 页面只决定内容、调用顺序与已有业务回调，不再重新定义通用按钮的颜色、圆角和触控尺寸。
- 手机竖屏、手机横屏、桌面共享相同组件合同，布局差异有显式条件。
- 旧主题可继续服务未迁移界面，但不得继续控制已迁移组件。
- CSS 重构批次与内容层级调整批次分开，可分辨是回归还是获准的视觉改变。
- 有组件状态预览、有真实流程证据、有旧规则删除登记，而不是只有新的 CSS 文件。

### 1.2 不以这些作为完成证明

- 创建了 token 文件，但页面仍使用散落的旧值。
- 包了一层 React 组件，但仍让三份旧样式决定按钮。
- 把 1200 行 CSS 拆成多个文件，选择器和竞争关系完全不变。
- 某个宽度截图漂亮，横屏与桌面没有检查。
- typecheck 或第 1 步移动预览通过，便声称六步全流程通过。

## 2. 范围和权限

### 2.1 纳入整理

1. 患者自助界面的六步页面、顶部/阶段栏、操作栏、提示、记录页和既有弹层。
2. 通用控件：动作按钮、答案按钮、辅助折叠入口、状态提示、卡片、标题、过渡卡。
3. 真实滚动容器、底栏测量、定位与焦点等纯界面逻辑。
4. 共享组件在桌面、康复思路模式的回归保护。默认保持其原外观，不顺带设计专业工作台。
5. 开发侧受保护预览场景及交接文档。

### 2.2 可改文件区

- `src/features/rehabmind/components/**`：仅显示结构、语义和瞬时交互。
- `src/features/rehabmind/styles/**`：样式所有权整理。
- `app/layout.tsx`：仅必要的样式入口调整；不改路由与权限。
- `src/features/rehabmind/test-workbench/**`：仅经既有保护入口提供预览，不改变生产路径。

### 2.3 明确禁止

- 修改 `src/domain/**`、`src/knowledge/**`、持久化/API/同步与身份相关实现，以配合 UI 重构。
- 改临床候选、排序、剂量、阈值、停止/转介条件、复测义务、评分未选与 0 分语义。
- 改快照版本、IndexedDB 结构、保存行为、案例和会话标识。
- 修改 B 类文件：`tests/**`、`docs/quality/**`、`release.generated.ts`、`artifacts/**`、`scripts/quality/inspect-local.mjs`、`docs/handover/test-session-handoff-*`。
- 把真实患者资料复制进预览样例、截图或日志；只用合成场景。
- 为进入总结页绕过门禁、注入伪 DOM、暴露未授权的生产测试入口。

运行既有测试可产生正常产物，但不允许手工改产物伪造通过。测试新增由负责人转交测试侧。

## 5. 样式所有权与隔离策略

### 5.1 采用 CSS Modules，不全库切换 cascade layers

新组件内部使用 CSS Modules，使专用类名不再被旧 `.rm-page-actions button` 等规则接管。全局 CSS 只负责根 token、应用骨架、必要 reset 和明确的兼容规则。

CSS Modules 并不能隔离元素选择器或继承。因此迁移时必须审计所有仍会命中的 `button`、`summary`、`.rm-app button`、后代选择器和伪元素。

**本轮不把三份旧 CSS 一次包进 `@layer`。** 未分层样式、分层样式与 `!important` 的优先级差异会改变全库行为；不能用这个动作假装解决竞争。

### 5.2 原子迁移单元

每迁移一个组件，必须在同一个批次完成：

1. 列出所有真实消费者与旧匹配选择器。
2. 记录基线 DOM、计算样式、行为回调与截图。
3. 建立新实现；迁移一个真实消费者验证后，再迁移同类消费者。
4. 对已迁移元素停止使用旧视觉类，或在旧规则中明确排除该迁移根。
5. 删除失去消费者的旧规则；仍用于思路模式/桌面的规则缩小范围，不全局删除。
6. 验证状态、竖横屏与桌面，更新所有权台账。

不得让旧类继续命中，再用更长的新选择器赢一次。若保留旧类用于测试定位，必须明确排除其旧外观规则；优先保留稳定 `data-*`，测试定位变动登记给测试侧。

### 5.3 属性唯一所有者

| 属性类别 | 所有者 | 页面能否覆盖 |
|---|---|---|
| 颜色/字体族/间距刻度 | token | 只能选择已定义语义 |
| 按钮尺寸/圆角/焦点/禁用 | Button组件 | 不可按页面重写 |
| 卡片内部排布 | 该组件module | 不可由父页穿透控制 |
| 页面区块顺序/区块间距 | 页面布局 | 可以；不能改子控件皮肤 |
| 底栏固定、排列、层级 | ActionRail | 页面只提供动作数据 |
| 底栏测量与内容避让 | 应用壳唯一测量者 | 不可各页另算一份 |
| 结果的视觉tone | 阶段展示适配 | 使用可靠既有事实，不改变领域规则 |

约束：新 module 不使用 `!important`；选择器通常不超过组件类＋状态/直接子类；禁止 nth-child/first-child 判断动作语义。必要的旧 !important 清除须先查消费者，登记清除位置。

## 6. 三个独立维度：模式、视口、迁移状态

不能继续把 `data-mobile-ui="v2"` 当成三者的组合。

1. **模式**：从现有产品模式/权限投影获取，自助与思路模式共享业务规则；不得使用屏幕宽度推断用户角色。
2. **视口**：由 CSS 判断宽度/方向，不存入业务状态，不通过 JS user-agent 分型。
3. **迁移状态**：开发期可用组件专属类或 `data-ui-component` 表示已迁移；不持久化、不暴露用户设置、不新建长期 v3 双实现开关。

P0 必须确认现有模式值和生效入口，再决定是否需要只用于表现的 `data-presentation` 根属性。不能因为名字像 guided 就自行推断患者权限。

推荐布局条件：

- 正常窄屏：≤359px；核心测点320px。
- 正常手机：360–720px。
- 矮宽手机布局：landscape、宽≤1024px、高≤600px。
- 其余为桌面/中间宽度回归区；721–820px不能成为无导航空档。
- ≤240px仅额外压力场景，不代替真字号放大。

组件基础皮肤在所有视口有效；媒体查询只改排列与必要密度。这样横屏不会因为遗漏一条媒体规则退回原生按钮。

统一手机条件允许由同一响应式文件投影为继承变量，例如内容边距/栏排列参数。CSS Modules 需要结构性媒体查询时允许重复条件字面量，但在台账中登记并核对；不要依赖当前构建未支持的自定义媒体语法，也不为此安装编译插件。

## 7. 最小组件合同

### 7.1 ActionButton

- 原生 `<button>`，默认 `type="button"`，支持原生事件、disabled、aria属性、id和原有测试属性。
- 外观 variant：primary/secondary/quiet/danger；尺寸默认52px最小高度，紧凑44px。
- 长标签可换行且自动增高，不设截断/max-height。按钮宽度由容器分配。
- 视觉 variant 与操作栏 position/role 分离：“保存”不因返回在左就获得危险色。
- 链接仍使用 `<a>`；不把所有交互变成可点击 div，不做万能 asChild 多态框架。
- 原生 disabled 不可点击；理由由描述区呈现。aria-disabled 如确有需求需同步抑制事件，不可只加属性。
- 不接受 className 穿透改皮肤作为常规用法。需要布局时外层负责；必要扩展须写明职责。

### 7.2 ChoiceButton / ChoiceGroup

- 动作按钮与答案选项分开。单选组优先原生 radio 语义，或保留按钮并使用一致的 aria-pressed；同一组不能混搭两套语义。
- 迁移若改成radio，必须保留原有回调时机，不引入选中即自动推进等新行为。
- 多选用checkbox或正确的切换语义；不因数组为空自动选择默认项。
- selected 同时驱动可见标记、边框与可访问语义；禁止仅靠底色。
- group 有可读问题标签，顺序合理；禁用和未选清楚区分。
- 安全“有/没有”、疼痛0/未选、无法完成等业务含义不变。

### 7.3 Disclosure

- 复用原生 details/summary；summary 至少44px点击高度，图标和文本对齐。
- 辅助说明可折叠，必答内容/当前安全限制不可默认折叠隐藏。
- 记录管理、案例更多、原理/退阶说明使用同一基础控件；管理内容允许不同tone，不复制默认三角小字。
- 若受控展开，必须维护现有状态并检查焦点；不引入全局折叠状态仓库。

### 7.4 StatusNotice

- tone：neutral/success/warning/danger；布局与配色随tone统一，不凭父卡深浅继承文字颜色。
- 普通状态 `role=status` 或静态说明按用途选择；不把每次重渲染都变成读屏警报。
- 支持一个就近辅助动作，使用 ActionButton；重要失败不能只存在于短暂Toast。
- 消息文本由调用方提供，不推断临床结果和保存成功。

### 7.5 TaskHeading / TaskCard

- 标题、当前任务进度和必要说明各有专属slot；无内容的 eyebrow 不输出空占位。
- 进度只显示一次同语义信息；“当前第1项”和“已完成5/5”需要明确标签，不能只堆数字。
- 窄屏徽章让位于长标题，可换到独立行；不因徽章将末字挤出。
- 卡片基础为白底/轻边框；状态色用局部标签或边线，不每张卡都大渐变。
- 一屏优先一个当前任务；有用长说明允许滚动，不能硬塞一屏。

### 7.6 StageTransition

- 独立明确的内容区与操作区；两段DOM对应两段布局，不依赖装饰节点占行。
- 手机≤359px次操作在上、主操作在下；≥360px空间足够可横排。
- 桌面按钮保持内容驱动，目标约48–58px普通高度，不伸展成整张卡。
- “完成了什么 / 下一步是什么”各说一次；保留主动确认，不自动跳步。
- `ui-primitives.tsx` 可保留原导出签名转接新实现，降低调用方变动。

### 7.7 ActionRail

输入建议为有限动作列表；采用现有数据，不搬入领域分支：

```ts
type RailAction = {
  id: string;
  label: string;
  placement: 'primary' | 'secondary' | 'tertiary';
  variant?: 'primary' | 'secondary' | 'quiet' | 'danger';
  disabled?: boolean;
  describedBy?: string;
  onClick: () => void;
};
```

- 阶段展示适配先决定哪些合法动作位于栏内、哪些为正文替代出口；组件不得按容量截断数组或隐藏安全动作。
- 1/2/3项布局自动根据实际列表选择，纯返回状态允许无primary。
- 同一槽位不允许两个动作。开发期报告配置错误，不能静默丢按钮。
- 额外业务出口用正文 ActionButton 显示，全部回调保持。
- 操作栏实际DOM顺序与视觉顺序尽量一致，Tab不按另一套顺序跳跃。
- 固定栏不能放在具有 transform/filter/动画变换的祖先下；避免页面入场动画期间固定栏相对祖先定位。检查稳定帧也检查切换过程。
- 优先复用应用壳已有唯一高度测量；迁移选择器需同批调整，不能同时留下两个observer。
- 测量包含padding和安全区，内容避让只消费一次该高度；不能把测得高度设回栏本身min-height。
- 普通100%三按钮目标不超过约120px（安全区另核），字体放大时允许增高，不能硬裁。

### 7.8 定位、焦点、Toast

- 定位第一未答项使用稳定DOM id/ref，限制在当前页根下，不用全document碰运气匹配。
- 切换训练动作后，等待目标提交到DOM再定位；不能 setState 后立即查询上一动作节点。
- 定位后使问题标题/首个答案在可视区；按交互需要聚焦可聚焦标题或控件，不能只滚动却让键盘留在页尾。
- Toast继续复用当前消息状态；定位由壳协调，不在每页算bottom。
- 有栏时保持至少12px距离；无栏时也检查正文按钮。必要时改为页内非覆盖状态区域，不用pointer-events:none掩盖视觉遮挡。
- 既有弹层关闭/焦点恢复机制继续复用；不新建第二套全局滚动锁。

## 8. Token 规格与设计约束

沿用已确认风格，不另创配色：背景`#f5f7fa`、表面`#fff`、正文`#202838`、辅助`#596579`、主色`#5659c9`、改善`#237a68`；警示/危险沿现有语义变量。

- 字体使用现有中文系统无衬线回退；正文16px、辅助14px、主标题24–28px、问题标题18–20px。
- 主按钮48–52px最小高度；非关键紧凑操作点击区域至少44×44px。这是产品要求，不冒充外部标准统一硬门槛。
- 间距以4/8/12/16/20/24为主；圆角控件10–12、卡片12–16。
- 关键正文不小于14px；12px只给非关键元信息，不把剂量/风险写成小字。
- 正文对比度目标至少4.5:1；测实际前景和背景，不能只查“非白色”。
- 禁止把已复查等同改善；可靠既有状态不足时用neutral，文字保留。不新增领域状态或解析中文字符串决定tone。
- 只在当前任务使用细靛蓝强调；“下一阶段”改轻辅助区。风险信息强于装饰，原理弱于操作。

Token先定义后必须有消费者；P6报告未使用token并删除无用途项，不以“以后可能用”保留一套空设计系统。

## 9. 三张必交台账

保存到开发侧交接文档，可合并为一个文件，不能新建多份相互矛盾的规范。

### A. 样式所有权

| 组件 | 消费页面/模式 | 原选择器和文件 | 新所有者 | 兼容项 | 删除项 | 验证证据 |
|---|---|---|---|---|---|---|

### B. 行为等价性

| 场景 | 基线合法出口及回调 | 迁移后出口及回调 | disabled条件 | 数据来源 | 差异说明 |
|---|---|---|---|---|---|

基线必须从原提交读取，不能用新代码同时充当新旧证明。文案/样式变更与临床行为差异分开记录。

### C. 验收

| 场景ID | SHA | 模式 | 实际视口/字号方法 | 可见业务标题 | 证据路径 | 代码/组件/流程层级 | 结果 |
|---|---|---|---|---|---|---|---|

结果只用：未实施、实现待验、通过、失败、阻塞、负责人批准延期。空白不得视作通过。

## 10. 分批实施

### P0：冻结范围与基线，先补可观察性

工作：

1. 搜索适用指令，读取文档、当前入口和调用链。
2. 列出通用组件消费者、CSS来源、模式差异、现有测试定位依赖。
3. 建立三张台账；先登记已知失败：桌面过渡按钮、横屏反馈按钮、20px管理入口、总结语义色、答案选中语义。
4. 保存320/390/844横屏/1280桌面的基线证据；记录当前状态与实际尺寸。
5. 复用受保护测试工作台建立组件状态预览。现有保护不可解除；不可新增公网无鉴权preview路由。
6. 若需要新增回归，先登记场景给测试侧；对其未接入状态明确标记。

退出条件：能够稳定进入需要修的真实页面；无法到达的场景有阻塞说明；所有权台账覆盖本轮组件。此批不开始大规模换CSS。

### P1：最小控件垂直切片

工作：

1. 建立token与ActionButton、Disclosure、StatusNotice最小实现。
2. 首先迁移反馈定位按钮、记录管理和案例更多入口，验证默认/焦点/禁用/展开/长标签。
3. 新控件在所有视口有基础皮肤，再增加布局差异，避免横屏默认样式回退。
4. 移除已迁移控件旧规则；保护未迁移消费者。

退出条件：320/390/844/1280组件预览与真实消费者一致；反馈按钮及summary≥44px；无新增样式覆盖债。不能只做预览不接真实页面。

### P2：共享布局与操作栏

工作：

1. 迁移StageTransition，修复桌面三行网格与手机布局。
2. 迁移ActionRail，按普通单/双/三操作→双侧出口顺序替换。
3. 逐处对照回调、disabled条件和原可用出口；安全分支不强制前进primary。
4. 接入唯一测量者，清理重复高度计算；核查内容尾部和Toast避让。
5. 检查动画祖先、弹层层级、真实滚动容器。

退出条件：桌面按钮正常；主操作/Tab顺序一致；双侧全部合法出口保留且可执行；栏和正文不遮挡。双侧流程证据缺失时本批只能标实现待验。

### P3：标题、卡片与答案控件

工作：

1. 迁移TaskHeading/TaskCard与ChoiceButton；先安全问答、再检查/反馈。
2. 取消重复同语义进度和动作名；长标题让徽章换行，不缩字。
3. 选中态同步可访问语义；补键盘交互检查。
4. 缺项定位统一为当前页稳定目标；训练切换后定位到新节点。

退出条件：0分/未选、单选/多选、不会做等行为不变；标题不孤字挤压；状态可被读屏识别；无新增自动推进。

### P4：六步内容层级与结果语义

此批才做获准的信息重排，不能混在纯等价CSS迁移中。

| 页面 | 本批动作 | 保留项 |
|---|---|---|
| 症状 | 单一示例、简短标签、完成状态→主按钮上下排列 | 解析、逐项/全部切换、缺项和安全分流 |
| 关键确认 | 已答进度、缺项定位、统一答案控件 | 每条安全项、原有顺序与门禁 |
| 评估 | 当前任务→怎么做→作答→解释；减少重复标题 | 图示、条件追问、评分与左右侧 |
| 处理 | 操作先于原理；结果正文左对齐、减少套卡 | 剂量、停止条件、全部安全出口 |
| 训练 | 单动作不显示无效翻页；说明→反馈→辅助内容 | 快速反馈映射、低负荷限制、加重流程 |
| 总结 | 变化→当前安排→复查→风险→详情；正确tone | 未解决问题、补查义务、真实保存状态 |
| 记录 | 问题优先、编号辅助、管理入口弱化但可达 | 案例/会话层级、恢复、复制、删除确认 |

结果配色适配只消费已有可靠可比事实。无法证明比较条件时显示原文＋neutral，不能为给卡片上色重写临床结果函数。

退出条件：对照原全面整改单U01–U15逐项有状态；未做项需明确延期裁定，不能因组件重构完成便全打勾。

### P5：跨视口、弹层与完整场景验收

完成§11矩阵。每个失败回到对应所有者修复，不回万能CSS文件追加覆盖。测试侧补充正式回归，开发侧交付真实交互证据。

退出条件：关键路径无按钮覆盖、关键文字不可读、错误风险色、无法定位缺项；受保护测试没有新增未解释失败；真机缺失仍列待验，不授予最终发布结论。

### P6：删除兼容债与交接

1. 搜索迁移旧类、旧规则和临时分支的所有消费者；确认零消费者后才删除。
2. 清理未使用token、重复媒体规则、不再需要的旧伪元素和临时注释。
3. 更新所有权台账和组件README：新增按钮该用什么、改布局到哪里、禁止什么。
4. 样式入口只调整一次并验证开发与生产构建；不要留下双重导入。
5. 未迁移的旧页面明确列出；不要求本次消灭三份CSS全部行数，但要求已迁移组件不再被它们控制。

退出条件：每个迁移组件唯一外观所有者；无“最终补丁区”；没有永久新旧双套实现；交付清单与证据绑定具体SHA。

## 11. 验收矩阵与证据标准

### 11.1 三层证据必须区分

1. **组件预览**：合成props渲染真实组件，证明尺寸、状态、布局；不得冒充真实六步流程。
2. **真实场景**：由受保护场景或正常交互进入实际阶段，使用真实组件、状态编排和回调。
3. **全流程**：从入口经过合法门禁完成流程；证明接线。不能由若干直达截图拼成全流程声明。

### 11.2 组件与视口

| 组件 | 状态 | 必测尺寸 |
|---|---|---|
| Button/Choice | 默认、禁用、选中、焦点、长文字、危险 | 320/390/844×390/1280×800 |
| Disclosure/Notice | 折叠、展开、长文字、带操作、读屏播报 | 同上 |
| Rail | 1/2/3动作、正文替代出口、禁用、Toast、动画切换 | 320/360/390/430/横屏/桌面 |
| Transition/Heading | 长标题、无副标题、不同阶段 | 手机＋桌面；检查按钮实际高度 |
| Summary | 改善/未变/加重/未复查、单/多动作 | 320/390/横屏 |
| Records/Dialog | 空/多案例/长历史、展开管理、取消确认 | 320/390/横屏/桌面 |

补充：412×915、721/820/1024宽度检查断点过渡，不要求所有状态做笛卡尔积；每个公共组件至少全主视口，每页至少320/390/横屏，每个特殊分支至少一主视口与最窄视口。

### 11.3 实际流程场景

- 第1步空/长输入、全部信息缺项/完成、输入键盘。
- 第2步第一项已答而后项未答；定位目标不是第一项；影像未答；安全分流。
- 第3步长名称、无法完成原因、0分/未选、双侧、位置图。
- 第4步普通处理、未改善、加重、双侧未完成且另一侧待处理、两侧完成、保存退出。
- 第5步0/1/多动作，当前动作与第一未反馈动作不同，低负荷、加重。
- 第6步正常/未变/加重/未复查、保存前后、后续康复。
- 记录页空/非空/长历史；管理展开与取消，不未经授权清空真实记录。
- Toast和底栏1/2/3按钮、无栏、抽屉、软键盘组合。

### 11.4 字号与真机

- 真实浏览器125%/200%或实际文字放大：记录方法、实际视口和浏览器版本；文字可读、控件可用、焦点不被遮挡。
- 320 CSS px重排与200%文字放大分开验收；缩小viewport＋DPR不等于真实放大。
- Android Chrome、iPhone Safari检查键盘、安全区、内部滚动与弹层。未取得设备时写“待真机”。
- 不用仅 `scrollWidth<=clientWidth` 判断通过；还必须检查裁剪、元素相交、末项可达与可执行操作。
- 对比度按最终实际背景计算；结果标签不只靠颜色。

### 11.5 测试侧分工

开发侧提供组件合同、场景ID需求、失败复现、基线SHA和修复SHA。测试侧拥有 `tests/**`，补能在错误基线上失败的回归用例。

如果测试尚未提供，开发可继续安全的局部实现与手工验证，但最终状态保持“待正式回归”；不得自行修改过期测试副本制造绿色。

## 13. 回退、暂停与禁止绕路

- 每批只改限定组件及消费者，保持可回退差异；不得夹带格式化全库或业务重构。
- 如果只能靠新增!important、重复全局observer或修改领域条件才能通过，停止该批，说明问题和所需裁定。
- 无法证明某旧规则无消费者时不删除，标记兼容范围与退出条件。
- 回退只针对本批可识别的修改，保留用户改动；不使用 `git reset --hard`，不盲目checkout整个目录。
- 不永久保留双渲染，让CSS隐藏其中一套；这会重复事件、焦点和业务入口。
- 不复制整个工作台用于“手机专版”；不把所有页面转换成配置驱动表单引擎。
- 不从真实数据生成固定mock以跳过流程；预览数据必须合成且标明证据等级。
