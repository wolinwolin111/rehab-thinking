## 1. 总体判断与本轮方向

目前的浅色底、靛蓝主按钮、轻量卡片可以保留。不需要重新换一套视觉主题。

真正影响患者使用的不是“所有按钮都太小”，而是信息和操作的优先级不够稳定：

- 顶部品牌、阶段栏、正文步骤标签重复占空间；正常窄屏又把“本次记录”压成小方块。
- 有些页面先解释原理，再展示患者应该怎么做；必填反馈离禁用的主按钮较远。
- 同一屏有多个大框、粗标题、色块和按钮，但患者最需要的“现在做什么”不够集中。
- 单动作训练仍显示两个不能使用的翻页按钮；过渡页保留大型数字装饰。
- 安全信息、普通完成状态和下一次安排，需要更严格地区分视觉语义。
- 现有验证报告混用了文件名、页面状态和缩放概念，不能作为完整验收依据。

设计方向：**一屏一个当前任务；怎么做优先，原理按需查看；一次一个明确的主要前进动作。**

这里“一屏一个任务”不是要求所有内容塞进一屏。长说明可以滚动，不能通过缩小字体、截断安全内容或固定卡片高度制造“一屏”。

## 5. 统一布局与组件规格（U04、U05）

### 5.1 视觉方向与令牌

沿用现有色彩，不增加第二套主题：背景 `#f5f7fa`、表面 `#ffffff`、正文 `#202838`、辅助 `#596579`、主操作 `#5659c9`、改善 `#237a68`。警示与危险继续使用现有语义变量，不额外硬编码一批近似色。

采用中文系统无衬线字族：正文和标题共享可靠回退；标题用 650–700 字重形成层级，正文 400–500，按钮 600–650。数字只在评分/次数中使用等宽数字特性，不引入与中文割裂的装饰英文字体。

保留的识别特征是“当前任务的细靛蓝边线”，一屏只强调当前任务，非所有卡片都加彩色顶边、渐变和阴影。

| 项目 | 默认规格 | 约束 |
|---|---|---|
| 页面左右边距 | 320px 为 16px；360–430px 为 16–20px | 不累计容器边距挤成窄条 |
| 主卡内边距 | 16px；320px 可为 12–14px | 尽量一层卡，不超过两层可见边框 |
| 主标题 | 24–28px，行高 1.3–1.4 | 不固定高度，不因长标题缩成小字 |
| 当前问题/动作标题 | 18–20px，行高 1.4 | 通常不超过两行；长内容自然换行 |
| 正文/问题/操作说明 | 16px，行高 1.5–1.65 | 关键内容不降到 12–13px |
| 辅助说明 | 14px，行高 1.5 | 12px 只用于非关键元信息 |
| 主按钮/答案按钮 | 48–52px 最小高度；文字 16px | 长文案允许增高，不设 max-height 截断 |
| 次级紧凑控件 | 点击区域至少 44×44px | 图标可小，命中区不能小 |
| 按钮间距 | 通常 8–12px | 文案长则换行，不靠极窄缝隔开 |
| 圆角 | 按钮 10–12px、卡片 12–16px | 状态标签可胶囊，长操作不做胶囊 |
| 区块间距 | 16–24px；区块内 8–12px | 删除纯装饰大空区，不压缩呼吸空间 |

以上 44/48px 是本产品的患者触控目标，不宣称 WCAG AA 一律要求 44px。WCAG 2.2 的最小目标条款为 24×24 CSS px，并存在间距等例外。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

### 5.2 顶部

目标：品牌栏约 56px；阶段栏约 44–48px（普通字号的设计预算，不是固定裁剪高度）。患者先看到任务，不先读三遍步骤编号。

实施：

1. 320–359px 保留图标品牌即可；“本次记录”恢复单行，宽度约 72–80px、高度至少 44px、字号至少 14px。
2. 更多按钮保持 44px 命中区。正常 320px 不使用 12px 两行记录按钮。
3. 只有极窄/真实放大导致容纳不下时，才使用紧凑布局；不能把正常 320px 与极端压力视口混在同一个规则里。
4. 阶段栏保留“3/6 · 评估检查”和“查看阶段”；正文小字不再重复同一组序号，只保留有用的子任务信息。
5. 不删除真实子流程进度，例如“第2个检查 / 共4个”。
6. 检查阶段按钮目前 38px 的规则，将实际命中高度提高到至少 44px。

验收：320/360/390 无重叠；顶部记录单行；正文首个任务不因冗余装饰被挤出首屏。若读屏名称与视觉短文案不同，读屏仍说明完整操作含义。

### 5.3 操作栏

保留现有角色驱动和实测栏高机制，不恢复固定像素偏移。

- 单按钮：主操作整行。
- 双按钮：宽度够时返回在左、前进在右；320 下长文案纵排，主操作最后。
- 三按钮：两次操作上行、主操作下行；没有足够空间时允许增高，不能为守住 120px 缩小关键文字。
- 100% 普通三按钮栏目标 ≤120px，不含设备额外安全区；125%/200% 不适用硬高度上限。
- 四出口：底栏最多三项，其余放正文可见的“其他选择”区域；保留全部回调。
- 不为了“一屏唯一主操作”隐藏处理加重、停止或保存的合法安全出口。
- 页面尾部留白来自真实底栏测量＋16–24px，不重复叠加多份 safe-area。

### U03：双侧出口与 Toast

双侧必须实测：未完成评估＋另一侧有待处理、未完成＋无待处理、评估已完成、安全信号/加重、保存稍后继续。

- 每个分支确认可见按钮数、角色唯一、真实矩形不相交。

- 底栏最多三项；所有合法业务出口都可找到；选中出口后确认实际去向。
- 对纯停止/返回状态不要强行制造“继续训练”主操作。

Toast 必测：初次建案、保存总结、单/双/三按钮栏、无固定栏、长文案、抽屉打开、软键盘打开。

- 有栏时与栏顶部至少 12px；无栏时不能因贴底遮住正文继续按钮。
- 若简单动态 bottom 仍遮正文，优先使用不覆盖内容的页内反馈区域；不要用 pointer-events:none 掩盖视觉遮挡。
- 安全/失败消息需持续可见，不只存在于自动消失 Toast；普通成功消息不强迫二次确认。
- 保留关闭能力与适当的状态播报，不把普通成功信息设置成频繁打断读屏的警报。
