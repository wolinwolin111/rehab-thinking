## 2. `DEF-RETEST-01` 详细整改

### 2.1 原问题

案例 `ME2RLABN` 中，“上下楼或下台阶”进入了问诊动作列表，`function:knee-step-down` 也实际记录为因疼痛无法完成，评分为 8/10。但已有处理记录只保存膝关节伸直、屈曲活动度复测，未保存下台阶完成状态复测。

这不是“所有问诊动作都必须复测”。只有用户在评估页真正尝试过、且评估记录允许进入复测的动作，才形成复测义务。害怕尝试、没听懂或没有实际尝试的项目不生成复测。

### 2.2 新数据合同

- `TrialTarget.functionRetestObligations`：处理前待完成的功能复测清单。
- 每项包含 `assessmentId`、用户可读动作名、首次完成状态、复测模式和可选首次分数。
- `TrialRecord.functionRetests`：按 `assessmentId` 保存每个动作处理后的完成状态、原因和可选评分。
- 旧的单动作字段继续读取和写入，不升级快照版本，schema 仍为 v2。

### 2.3 流程规则

1. 处理项目可以合并，但合并处理目标时必须合并全部功能复测义务。
2. 首次能完成但有不适：处理后先确认能否完成；能完成时再记录同一动作评分。
3. 首次因疼痛或无力无法完成：处理后只比较完成状态，不把未完成动作转换成普通前后分数。
4. 首次能完成、处理后无法完成：按加重处理并停止同类后续处理。
5. 多个动作必须逐项完成；任何必需项未回答，继续按钮保持禁用。
6. 聚合结果采用保守口径：任一动作加重即 `worse`；全部改善才是 `better`；部分改善为 `partial`；其余为 `same`。

### 2.4 页面表现

- 复测页按动作显示独立卡片和稳定的 `data-assessment-id`。
- 每项分别回答“能完成 / 还是做不完”。
- 做不完时分别记录“疼或不舒服 / 没力或撑不住 / 担心继续会加重”。
- 每项需要评分时只显示自己的评分控件，不共用其他动作的答案。

## 3. `DEF-DATA-THREAD-01` 详细整改

### 3.1 根因

旧实现把问诊字段每次变化都视为“主问题已经改变”：

1. 归档当前问题链；
2. 新建 `problemThreadId`；
3. 新建 `sessionId`；
4. 清空当前康复历史；
5. 发送 `problem_thread_archived` 事件。

因此一次正常填写会按每次点击生成一条短命问题链。`ME2RLABN` 的 23 条异常归档线程中，大部分生命周期只有 0.2～2.7 秒，标题依次记录了同一次问诊逐项补全的中间文本，证明它们不是 23 个真实康复问题。

### 3.2 命令拆分

`applyIntakeChange` 用于普通问诊编辑：

- 保持 `localCaseId`、`problemThreadId`、`sessionId`、`sessionStartedAt` 和已有康复历史不变。
- 只失效受问诊变化影响的安全、评估、处理、复测和训练状态。
- 不归档、不新建身份、不发送归档事件。

`startNewProblemThread` 只用于用户明确选择“出现新问题”：

- 当前问题最多归档一次。
- 新建一个问题链和一次康复记录身份。
- 旧问题及其康复历史继续保留在同一案例中。

### 3.3 历史投影维护工具

工具：`scripts/data/repair-problem-thread-projection.mjs`

默认 dry-run：

```text
node scripts/data/repair-problem-thread-projection.mjs --case=ME2RLABN
node scripts/data/repair-problem-thread-projection.mjs --known-cases
```

明确应用：

```text
node scripts/data/repair-problem-thread-projection.mjs --known-cases --apply
```

安全边界：

- 只清理状态为 archived、生命周期不超过 5 分钟且没有临床证据引用的瞬时线程。
- 保留 active、resolved、superseded、被新问题引用、含完成记录或被人体标记/评分/备注/决策记录引用的线程。
- 只移除随被清理线程产生、没有临床证据引用的 draft 会话索引。
- 不删除、不更新 `case_events`。
- Apply 前使用 SQLite 在线 backup；事务内校验旧 revision，避免覆盖并发修改。
- 每个修复案例写入 `snapshot_projection_repaired` 管理审计。

## 4. `DEF-UI-MULTI-CHIEF-01` 详细整改

- 多动作总结标题统一为“本次不舒服的动作”。
- 每个动作单独一行，使用纵向列表和分隔线，不使用标签、横向网格或拼接长标题。
- 删除“当前诱发动作”整栏和重复规则提示卡。
- 未完成总结提示：“后续会按评估中实际做过的动作，逐项查看变化。”
- 无固定动作提示：“这次没有固定的加重动作。”
- 已保存总结复用同一组件，避免恢复后重新变成长字符串。
- 单动作仍可显示前后评分，但不再重复动作名称。
