# 真实页面闭环验收

当前系统测试契约统一记录在[首发场景验收](../pilot-scenario-coverage.md)的“当前系统测试契约”章节。本文件只保留真实浏览器的操作纪律、页面断言和实际走读记录。

## 目的

源码断言只能证明“代码里有这段文字”，不能证明用户真的能点击完成流程。每次评估/处理规则调整后，必须在桌面浏览器从新评估开始，按页面实际按钮走到总结或明确停止出口。

## 每次点击的验收纪律

1. 只点击当前 `domSnapshot()` 中可见的按钮，不按旧快照连续盲点。
2. 每次点击后立即重新读取 `domSnapshot()`，记录阶段、标题、当前按钮和已收集信息。
3. 检查“下一步”是否在信息足够后才启用；不能出现无按钮、禁用按钮却没有补充提示、自动跳过未填页面。
4. 每个阶段都读取浏览器 error 日志；出现报错、卡死或意外跳转，立即停在现场记录，不用源码推测“应该可以”。
5. 从返回上一步重新进入时，重新确认已选值、评分、复测结果和处理队列是否仍是最新数据。

双侧路径额外遵守以下浏览器断言：先在同一主要大部位选择左、右两个具体位置，重新读取页面后两条记录都必须可见；优先侧未选择时不能进入关键确认；每个评估项目必须保留左右结果，主诉优先侧与项目更差侧冲突时只能出现提醒；同一处理目标只显示一张双侧处理卡，左右执行状态分别记录；复测页分别记录左右结果；双侧针对性评估未完成时训练页只能显示低负荷出口，正常训练按钮不得启用。

## 固化的断言

`scripts/legacy-browser/real-browser-flow-audit.mjs` 提供统一辅助器：

- `auditCheckpoint`：检查当前阶段标题、必需/禁止内容、按钮或明确终止出口，并检查 error 日志；
- `auditPatellaGroup`：检查髌骨方向卡实际数量必须为4；
- `auditSummaryScore`：检查总结采用本轮最新主诉分数，而非首次分数；
- `auditNoRuntimeErrors`：检查浏览器 error 日志为0。

这些断言不能替代人工判断动作是否看得懂，但能把“没按钮、跳步、重复复测、数据回退、运行时报错”从人工印象变成每次走读都要记录的证据。

## 本轮新增闭环核对

1. 专业用户在“主动伸直受限 → 被动仍受限 → 膝关节伸直方向松动”后，页面不能把通用膝关节候选误显示成髌骨专项复测。
2. 真正进入髌骨方向候选时，标题必须是“髌骨向上/下/内/外滑动辅助”，处理卡只复测本轮实际受限的方向；不能把四个方向重新全部复测。
3. 髌骨复测必须使用“被动活动幅度”和“被动活动时有没有出现新的不适”，不能回退为主动活动或抗阻力量问题。
4. 普通用户的肿胀管理完成后仍必须出现已确认的肌肉/活动处理或明确的低刺激训练出口；急性肿胀、刺痛、麻电感场景不自动显示训练后自主按压。
5. 组合与极限场景至少覆盖：全阳性、全部“无法完成/暂不判断”、主诉分数下降但活动仍受限、活动接近健侧但力量偏弱、处理后加重、训练后加重、返回上一步修改、双侧主诉、第二次康复沿用上次结束分数。

## 第六批补充走读（延期入口不计入）

### C1 / 全部不会做或无法完成

以膝关节下楼主诉实际走读：台阶下降选择“做不完或不敢继续”，主动伸直和屈曲选择“无法完成/不敢或不会做”，局部专项选择“暂不检查”，肌肉触压选择“暂不判断”。结果符合以下要求：

- 不会把无法完成当成正常或活动阴性；
- 主诉动作保留为动作不适，两个主动活动保留为后续复查；
- 没有生成肌肉处理或关节处理；
- 处理页没有虚构处理记录，训练页仍可选择基础训练或“暂不训练，保存方案”；
- 选择暂不训练后，总结明确显示“方案已保存，未执行”，并保留后续复查项目；
- 由总结进入稍后反应记录后，只回到相关复查，不增加康复次数，已完成的其他评估保持锁定。

当前观察：训练页提供了脚跟滑动、臀桥、基础站立屈髋等基础动作；双侧评估未完成时已经显示“低负荷基础活动”提示和限制说明，正常训练路径不显示该限制。后续仍需收集普通用户对“低负荷基础活动”文案的理解反馈。

### C2 / 全阳性膝流程

实际选择活动范围异常、活动不适、功能动作不稳且有症状、局部检查出现提示反应、两处肌肉按压反应明显。结果符合以下要求：

- 评估结果按活动受限、肌肉紧张、力量与控制、动作不适和后续跟踪分类，没有把全部异常扩散成同类处理；

## 双侧处理卡验收

1. 评估页完成一个双侧动作后，必须能看到项目级的“左侧更差 / 右侧更差 / 两侧异常 / 两侧接近 / 暂不判断”结果；不能只保留一个未说明侧别的“更差侧”。
2. 同一肌肉或同一处理目标在左右两侧同时出现时，只显示一张处理卡；卡片显示左右的“当前 / 待处理 / 已完成”状态。
3. 完成优先侧处理后，按钮只推进到同卡的另一侧，不跳出一整套新的评估和处理页面；第一侧的执行结果不会自动填入另一侧。
4. 双侧复测必须逐侧记录“轻了 / 没变化 / 更重”；任一侧选择“更重”时不得继续同类处理或正常训练。
