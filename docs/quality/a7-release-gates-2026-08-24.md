## 发布验收发现并修复的问题

1. vinext 生产运行时没有应用 Next `headers()` 的完整页面安全头。通过 RehabMind 专用 Nginx snippet 补齐 CSP、frame denial、Referrer Policy、Permissions Policy、no-store 和 noindex，不影响同机 Clinic、Mobile 和 Shop。
2. `/etc/nginx/sites-enabled` 中两份 `combined.conf.bak-*` 被 Nginx 当成有效配置加载，导致同名 server 冲突。已移入 `sites-available/archived-baks`，配置测试无冲突。
3. PM2 `startOrReload` 没有更新既有进程 cwd，出现软链指向新版本、进程仍从已删除旧目录运行的假发布。发布、回滚和恢复统一改用 `vps-activate-release.sh` 重建进程，并在清理旧版本前核对 `/proc/<pid>/cwd`。
4. 原生产 HTTP 探针依赖后台列表第一页，数据增多后产生假失败。已改成按新建案例 ID 读取的最小纵向合同，并在 `finally` 中软删除测试案例。
5. dirty build 指纹原先包含验收后状态报告，更新报告会让自身证据过期。现仅排除状态/交接/质量报告，正式产品规则、实现、迁移、测试和发布脚本仍参与 buildId。
6. 首页虽然返回 200，但 Nginx 未代理 vinext 生成的根路径 `/_next/`，CSS/JS 请求被回退为 HTML，导致生产页面完全无样式。已增加明确的 `/_next/` 代理，并把“从真实首页提取关键资源后校验状态、MIME 和非 HTML 内容”加入 VPS 发布探针；Edge 实际渲染复验无控制台错误或横向溢出。
