# 膝关节与踝足首发版场景验收

更新时间：2026-08-16

> 状态：现行验收规范。产品、决策和知识内容分别见[产品规范](./rehabmind-complete-product-design.md)、[决策引擎规范](./rehab-decision-framework.md)和[首发知识库](./knee-ankle-pilot-knowledge.md)。

### 本轮已落地的动态决策回归

代码与页面回归必须同时覆盖以下闭环，不以“npm 测试通过”替代页面逻辑验收：

| 回归点 | 通过标准 |
| --- | --- |
| 肌肉处理后主动/被动均接近健侧 | 不再进入通用关节松动；仍有独立问题才继续 |
| 肌肉处理后PROM仍小于健侧 | 具备专业能力时进入对应方向关节处理；普通用户显示专业协助出口 |
| 同一方向历史受限、本轮已恢复 | 只保留本轮最新结果，旧记录不能重新打开关节候选 |
| 同一肌群影响多个方向 | 只生成一个处理单元，相关方向一次统一复测 |
| 复测后问题仍未解决 | 不显示静默结束；继续下一候选、训练、补充检查或保存退出 |
| 第二次康复 | 使用上次结束分数与最新方向状态；先快速复查必要项，再继续有效处理和训练 |
| 返回修改/保存恢复 | 清除受影响的旧候选与复测，按新版本从正确步骤继续 |

本轮自动化回归包含 249 项规则、页面字符串和工作流测试；新增的序列隔离测试验证旧处理序列的PROM不会重新触发关节入口。真实页面仍需按下方组合矩阵走读，并检查浏览器控制台无异常。

## 双模式重构与完整闭环测试计划

### 本轮动作收集与导航回归

- 症状收集阶段不再单独询问“哪个方向用力最容易不舒服”。用户先选择或填写“哪个动作最容易出现不舒服”，可多选；没有合适动作时保存自定义原话，选择“说不清/没有固定动作”也能继续。
- 动作选项使用“专业名称｜具体怎么做”的组合，例如“踝背屈｜把脚背向小腿方向勾”。用户主诉动作、关节活动方向和主动发力结果分开保存；同一个实际动作在评估卡内记录活动范围、动作不适和主动控制，不拆成重复动作。
- 逐项问答维护固定路径和当前位置。选择答案不自动跳题；“下一步”只进入路径中的下一项，“上一步”返回路径中的上一项。返回后再次点击下一步不得跳到第一个未填写字段；修改分支答案后只跳过已经失效且没有记录的后续字段。
- 自定义动作始终保存原文并作为主诉复测动作。没有标准关键词时不强行归类、不当作没有问题；专业人士可在后续手动归入已知动作类别。

### 测试目标

本轮不是只检查页面能否打开，而是证明：每个可见选项都有确定的数据含义和下游出口；两种产品模式使用同一临床核心但不同编排；任何正常、异常、未知、返回修改、保存恢复和后续康复路径都能结束在下一阶段、待补充、保存退出或专业评估，不允许卡死、静默结束和旧数据继续执行。

### 本轮专业/普通收集分流回归

| 场景 | 必须看到的界面与出口 |
| --- | --- |
| 普通用户 + 自我检查 | “确认你的症状信息”、逐题导航；不能看到专业备注、批量录入或被动能力字段；完成后进入关键确认 |
| 专业用户 + 自我检查 | “记录主诉与评估条件”、一次展开的结构化面板；保留患者原话和专业备注；只开放主动检查，仍可进入完整闭环 |
| 专业用户 + 协助他人 | 在同一结构化面板选择检查对象后显示能力矩阵；能力未确认时只停留在本阶段，不跳空白页 |
| 专业用户 + 64种能力组合 | 每一组都有明确的能力归一化结果；PROM、抗阻、末端感觉和关节处理按权限门控，不把备注直接变成 finding |
| 任意模式 + 自定义动作 | 保存原话；有标准词时建立动作关联，无标准词时保留待验证动作，后续不生成伪正常或伪异常 |
| 任意模式 + 说不清/没有固定动作 | 清除动作评分目标，不显示分数滑条；仍可补充位置、症状和目标，进入评估或明确待补充出口 |
| 任意模式 + 肿胀/按压痛/麻电 | 对应人体图分别记录位置；没有选择时可明确标记“说不清”，不会把主诉位置偷偷代替为症状位置 |
| 任意模式 + 返回修改 | 返回后仍停留原编排；普通用户按路径回退，专业用户继续批量面板；重新进入下一阶段前不会沿用已失效的旧计划 |

以上组合的页面闭环统一检查：症状收集 → 关键确认 → 评估入口 → 评估结果 → 处理/复测 → 训练 → 总结，或在任一安全/证据不足节点明确停在“补充检查、保存退出、专业评估”之一。没有“选完后自动跳题”“处理一项后静默结束”“返回后旧数据继续执行”三类出口。

### 第一层：权限和工作流配置穷举

对 `productMode × operationTarget × capabilities` 做纯核心穷举。能力使用6位布尔组合（PROM、抗阻、末端感觉、基础触诊、专项检查、关节松动），两种产品模式和三个操作对象共测试 `2 × 3 × 64 = 384` 组原始输入，并断言规范化结果：

- 自助模式无论能力输入如何都不开放PROM、人工抗阻和关节松动；
- 给自己操作不开放PROM、末端感觉、人工抗阻和自行关节松动；
- 给别人操作只开放已声明能力；
- 关节松动没有PROM和末端感觉能力时必须关闭；
- 只学习模式不写入真实案例、康复次数和复诊日期；
- 切换能力后旧计划版本失效，历史记录保留原能力快照；
- 任意非法或矛盾组合都被规范化，不产生空白页面。

### 第二层：每类选项的下游映射

为AROM、PROM、主动保持、抗阻、末端感觉、触诊、专项检查和功能动作分别遍历全部选项。每个选项必须只落到以下明确状态之一：正常、明确异常、症状问题、力量/控制问题、待确认、当前跳过或安全停止。

重点覆盖：正常、偏小、偏大、疼痛无法完成、害怕加重、不会做、看不出来、未测试、两侧接近、左侧更差、右侧更差、双侧异常、熟悉症状、新出现症状、无不适和多方向均不适。选择“不会做/未测试”后，依赖该动作的问题自动隐藏或变为待确认，不能继续要求填写动作后的疼痛选项。

学习解释单独做展示回归：开关前后决策输出、按钮状态和保存数据必须一致；实际操作默认关闭，案例走读默认开启；解释只允许在规定的分支节点出现。每条默认一句、必要时最多两句，建议30～50个汉字，不得包含内部算法词、诊断结论、长串肌肉名单或已经显示过的操作步骤。人工审核至少覆盖“为什么先检查”“主诉改善但仍继续”“转关节处理”“转主动控制”“证据不足”五类文本。

专项检查增加独立权限与触发矩阵：膝5项、踝足4项逐项覆盖“前提命中/未命中、自己/别人、能力具备/缺少、阴性/阳性/疼痛无法判断/未测试/停止”。验收要求：

- 定位筛查只生成位置证据，不出现结构诊断；
- 反应实验必须复测同一主诉动作，没有稳定变化时不提高处理优先级；
- 安全分流只改变影像、继续或停止出口，不生成处理；
- 专业特殊测试在给自己操作、能力缺失或触发前提不足时不出现；
- 专项阳性不能覆盖AROM/PROM、力量和基础功能结果；
- 急性崴脚四方向和膝伸屈基础组不能被专项检查挤掉；
- 麦氏、韧带稳定或踝稳定检查出现阳性线索时显示专业评估方向，不写成确诊；
- 返回修改受伤机制、位置或能力后，已经不再适用且尚未执行的专项检查立即退出队列。
- 正式影像或医生已明确对应结构时，删除只为重复确认该结构的专项测试；AROM/PROM、稳定表现、力量、功能和负荷耐受仍按康复需要保留；
- 影像结论不明确、当前功能与影像不一致或需要判断合并问题时，只允许专业人员按“结果会改变下一步”的原则补充测试；
- 同一结构已经由影像确认后，系统不能要求用户再次做出阳性测试才能进入保护、处理或训练路径。
- 上胫腓关节不要求微动或末端感觉答案；腓骨近端辅助后只复测原主诉和相关AROM，无变化时退出，不生成错位/复位结论；

### 第三层：首发部位临床组合矩阵

对大腿、膝、小腿和踝足使用成对覆盖矩阵，至少覆盖以下维度：

| 维度 | 取值 |
| --- | --- |
| 病程 | 急性、亚急性、慢性 |
| 侧别 | 单侧、双侧 |
| 主诉清晰度 | 明确动作、只有位置、没有固定动作 |
| 刺激类型 | 活动时、发力时、负重时、休息时 |
| 检查表现 | 全阴性、范围异常、症状阳性、力量/控制异常、全未知、全阳性 |
| 使用方式 | 自助、思路模式自己、思路模式别人、案例学习 |
| 目标 | 消肿、减轻症状、日常生活、恢复运动、高强度运动 |

自动生成不少于240个成对组合，并保留人工审核的代表性案例：膝下痛下楼、膝内侧痛、膝伸直受限、急性外踝崴伤、慢性踝背屈不足、小腿前侧酸痛、小腿内侧痛、大腿前/后/内/外侧问题。每个组合断言评估数量有上限、必查项存在、无关足趾或跨关节检查不混入、finding分类正确、处理和训练均有合法出口。

### 第四层：专业阶段处理和关节入口矩阵

至少覆盖以下组合：

| 肌肉阶段反应 | AROM | PROM/末端感觉 | 应有结果 |
| --- | --- | --- | --- |
| 改善 | 达到目标 | 任意 | 退出该活动问题，进入剩余问题或训练 |
| 改善 | 未达目标 | PROM仍受限 | 符合能力与安全条件时开放关节松动 |
| 无变化 | 未达目标 | PROM仍受限 | 一组高相关肌肉完成后开放关节松动，不要求穷尽所有肌肉 |
| 改善或无变化 | 未达目标 | PROM接近目标 | 转主动控制，不开放关节松动 |
| 任意 | 任意 | PROM未知 | 生成精确补充检查，不开放关节松动、不结束整个案例 |
| 任意 | 任意 | 硬性阻挡、锐痛或风险 | 停止关节处理并给出专业评估出口 |
| 加重 | 更差 | 任意 | 进入异常反应闭环，不继续本批次 |

同时验证同一区域只处理一次、同一批次只阶段性复测一次、主诉与相同活动方向共用分数、关节处理后统一更新AROM/PROM和主诉、未达到健侧不能被“已有改善”提前标记完成。

### 第五层：状态机和极端操作

使用纯状态模型进行有种子的随机动作走读：两种产品模式各不少于500条序列，每条最多100次操作。随机执行选择、取消、跳过、返回、修改能力、开关学习解释、保存、恢复、加重、重新评估、结束和开始下一次康复，并验证：

- 任意状态都有可见下一步或明确出口；
- 不出现无限循环和无按钮页面；
- 阶段完成条件和按钮禁用条件一致；
- 返回修改后只作废依赖旧答案的下游数据；
- 旧评估/权限版本的处理不能继续；
- 没有新处理时不重复复测；
- 同一实际动作别名只保存一次；
- 正式点击开始下一次康复前不增加次数；
- 保存恢复后回到同一模式、阶段、批次和未提交输入。

### 第六层：真实页面端到端

桌面浏览器至少完成以下24条完整路径：两种模式的膝和踝基础阴性/阳性流程，康复思路模式自己与别人操作，案例学习，PROM未知，关节入口开放和关闭，全部不会做，双侧，全阳性，高分停止，训练退阶，处理加重，相同答案聚焦复查，返回修改，能力切换，学习解释开关，中途保存恢复，第二次康复继续有效处理，第二次出现新症状，第二次训练加重和次日反应记录。

每条端到端路径必须从症状输入走到总结或明确停止出口，检查页面标题、专业术语、问题台账、阶段卡片、按钮可用性、控制台错误和保存后的重新打开。不能只用源码字符串断言替代真实交互。

### 发布门槛

- 当前自助基线测试全部通过，无既有流程退化；
- 权限穷举384组全部通过；
- 临床成对组合不少于240组全部有明确出口；
- 随机状态序列不少于1000条，无卡死和跨版本执行；
- 24条真实页面路径全部闭环，控制台零错误；
- lint、build、全量测试和 `git diff --check` 全部通过；
- 对关节入口、权限规范化和后续康复至少各保留一份人工审核结果后，才删除旧的 `userRole/examSetup` 页面分支。

## 本轮真实页面验收

| 场景 | 验收结果 |
| --- | --- |
| `漆盖疼` | 识别为膝关节，感觉记录为“疼痛，性质说不清”，不擅自解释为酸痛 |
| `脚腕疼了好几年` | 识别为踝足，时间为超过6周 |
| `昨天歪脚了` | 识别为踝足，机制为扭转或崴伤 |
| `ankle pain` | 识别为踝足，感觉记录为“疼痛，性质说不清” |
| `疼` | 不预设部位；一次只追问一个缺项，不在首屏展开整张表 |
| `右膝疼` | 已知右侧和膝关节后，先问具体位置；不重复询问左右侧 |
| `膝盖疼，脚踝也疼` | 不静默选择部位，先让用户确定本次优先处理膝盖还是脚踝 |
| `脚崴了` | 不猜具体区域，显示“没识别出部位”提示 |
| `走路时不舒服` | 识别为走路主诉，并自动勾选走路、站立或负重 |
| 双侧膝痛 | 活动度使用左侧更差、右侧更差、两侧都受限，不要求寻找健侧 |
| 膝关节自助专项检查出现异常反应 | 说明不能单独判断结构问题；允许继续其余低刺激检查，并提示持续、严重或卡顿不稳时线下确认 |
| 急性外踝崴伤 | 先完成3项骨性风险确认；随后四方向全部检查，背屈和外翻优先、跖屈和内翻次之；普通外踝主诉不出现足趾检查 |
| 急性崴脚且明确跖屈疼 | 先查跖屈，再按背屈、外翻、内翻补齐四方向；提踵或承重不能挤掉基础方向；跖屈取样同时包含小腿后侧和前侧 |
| 踝足6项均异常 | 评估摘要优先显示核心问题，核心处理限制为3项；普通用户不显示额外可选队列 |
| 无固定诱发动作且膝检查全正常 | 不生成主诉处理、候选处理或前后评分；直接显示“没有需要处理的问题”并给低刺激基础活动 |
| 用户说不清症状程度或当前没有固定症状 | 不显示评分滑条，不保存默认分数；允许继续评估，后续找到可重复不适时再建立基线 |
| 评分滑条 | 未操作时不记录；拖到6分并松手后直接写入6/10基线，不再多一次确认 |
| `两只膝盖一蹲就疼，左边更厉害，还会响，但不知道具体哪儿` | 识别为双侧膝、位置说不清、诱发动作蹲起 |
| `右脚踝疼了两三年，时好时坏，跑完球第二天酸` | 识别为踝足、超过6周、跑步及运动后出现 |
| `脚踝烧灼火辣` | 感觉识别为烧灼或火辣，不再留空 |
| `knee pain right side when squatting` | 识别为右膝和蹲起动作 |
| `左膝盖卡住，有时候像针扎，晚上躺着也疼，走路腿软` | 识别刺痛、夜间和走路负重；普通用户先进入线下确认 |
| 多项7～9分且多个动作因疼痛无法完成 | 评估结果页停止自助处理；顶部“处理复测”同时锁定，不能绕过 |
| 下楼膝内侧刺痛，检查发现膝伸直偏小 | 主诉仍显示“下楼梯”，不再错误合并成单一膝伸直活动 |
| 膝主诉5→3，膝伸直仍小于健侧 | 保留主诉改善，再复查膝伸直并进入主动控制，不被默认0分提前结束 |
| 膝关节主诉同时命中台阶或下蹲 | 可先复现主诉功能动作，但膝伸直、膝弯曲两项基础活动均保留；伸直排在弯曲前 |
| 普通用户膝后不能压平，但直腿抬高可保持 | 记录主动伸直偏小；按实际紧张位置进入一次轻柔肌肉处理，不生成自助关节松动 |
| 普通用户膝后可压平，直腿抬高时膝盖弯曲或明显抖动 | 记录伸直保持能力不足，移交股四头与末端伸膝控制训练，不要求当场反复复测力量 |
| 普通用户看不清膝后空隙或因疼痛无法抬腿 | 保留未知或未完成；不强行判断活动正常、关节受限或肌力不足 |
| 膝主诉5→2且刺痛已降为轻度 | 允许进入低负荷训练；刺痛≥4分时才建议先线下评估 |
| `没崴没撞` | 识别为没有明确受伤，不反向触发急性损伤路径 |
| `昨晚崴了右脚，外踝肿，脚趾没有受伤` | 识别为急性崴伤并进入骨性风险确认；直接记录外踝肿胀；“脚趾没有受伤”不覆盖整体机制，也不增加足趾检查 |
| 进入主诉复测 | 隐藏刚完成的处理卡，只显示主诉动作、处理前分数和新评分 |
| 踝背屈、外翻同时异常 | 一轮后同时复查；已接近健侧的外翻退出，仅继续仍不足的背屈 |
| 同一小腿后侧区域同时关联背屈、跖屈异常 | 小腿后侧只处理一次；随后分别做两个方向的低次数控制并统一复测 |
| 背屈已恢复、跖屈仍异常 | 后续同区域单元不再显示背屈控制或背屈复测，只保留跖屈 |
| 旧记录写“小腿前外侧”但没有肌肉或方向证据 | 保留原文，不直接生成含糊处理卡；要求补充前侧或外侧定位 |
| 膝伸直受限且大腿前侧检查明确异常 | 可优先处理大腿前侧；完成末端伸膝低次数控制后统一复测膝伸直和相关主诉 |
| 急性崴脚四方向均异常 | 四方向范围和不适先分别完成；肌肉紧张区域只合并检查一次，不在每个方向重复按压 |
| 跖屈初评7分、首次处理后4分 | 下一处理显示“处理前4/10”，滑条保持未选择；不得重新显示7分 |
| 点击“处理完成，开始复测” | 本轮复测方向被锁定并显示复测页，不能因候选更新直接跳到下一处理 |
| 第二次康复上次仅小腿前侧有效、本次小腿后侧明确紧张且背屈仍异常 | 小腿前侧保留优先级，小腿后侧可以作为本次新证据候选；不是只允许上次有效区域 |
| 股直肌与外侧链作为一个伸直处理单元后有效 | 记录组合有效，并分别保存主要目标、配合目标和未区分目标；本次不为拆分归因增加复测，下次优先单独验证最可能主目标 |
| 方向已恢复但相关肌肉仍明确紧张 | 不重开针对性处理；训练页显示一次简短训练前松解，完成后直接训练 |
| 踝外侧主诉、目标恢复跑步 | 训练覆盖背屈、外翻、足弓、单腿站、提踵与台阶 |
| 训练后不适更重 | 提示停止当前版本、改退阶；退阶仍加重则移除并列入下次复查 |
| 双侧急性崴脚，右侧更重 | 不擅自改成单侧；先让用户选择本次按双侧还是主侧记录，右侧信息不会覆盖左侧描述 |
| “右膝没固定动作、偶尔没劲” | 主诉动作保持待确认；“没劲”识别为无力或不稳及力量不足；诱发场景识别为没有固定动作 |
| 多选目前情况与诱发场景 | 选择一项后仍停留当前题，可继续选择；只有点击“选好了，下一步”才推进 |
| 中途返回上一题 | 原选项保持，不清空后续已解析信息；右侧字段可直接跳回修改 |
| 信息未收集完整 | 不显示“进入关键确认”；完成最后一项后才出现入口 |
| 影像选择骨折、韧带或肌腱结构异常 | 未选择医生允许时锁定评估入口并允许保存；补充医生允许后恢复入口 |
| 轻按清楚刺痛 | 处理候选排除按压刺激及关节处理，训练降为低刺激；特殊检查同时异常时结束自助路径 |
| 功能动作起始、末端、全过程不适 | 分别进入慢速控制、半程训练和高敏感保守版本 |
| 无主诉动作但膝伸直弱、下蹲或提踵异常 | 每一类评估发现都生成后续目标，不在一组兜底处理后直接结束 |
| 急性右踝崴伤、背屈受限并选择“小腿后面”紧张 | 肿胀只安排一次时间性管理；随后优先处理小腿后侧并复测背屈，不退回无关候选 |
| 双侧膝痛、右侧膝伸直更差、股四头力量偏弱 | 先右后左；处理、总结、历史记录和第二次康复均不显示 `5→0`；力量问题移交仰卧训练 |
| 功能动作选择“动作异常” | 同时出现代偿表现和发生阶段，两项未完成前不能结束该检查 |
| 非急性小腿前侧疼，背屈幅度接近对侧但复现熟悉酸痛 | 仍进入一次小腿前侧相关肌群轻按比较；明确异常进入“肌肉紧张”，两侧接近不生成问题 |
| 急性小腿撞伤且肿胀 | 不要求反复轻按肌肉，优先时间性管理和安全活动 |
| 处理5→7，停止后回落，复查答案与原来相同 | 仍可逐项确认新评估版本；旧处理方案在确认前不可执行 |
| 康复思路模式阶段工作台 | 评估项目、问题台账、处理复测、训练和总结均有明确阶段卡；进入评估时不出现空白工作台或运行时错误 |
| 踝足首次完整闭环 | 右外踝崴伤从症状收集、四方向活动检查、共享肌肉触诊、分组处理/统一复测、训练、训练后复测到保存总结均可完成；处理前5分沿用为后续3分、2分和最终1分 |
| 保存后第二次康复 | 恢复上次结束1分、上次有效处理和训练；先复查主诉、活动、肿胀及肌肉紧张，再进入本次处理，不重新使用首次评估分数 |
| 同一肌群关联多个方向 | 问题台账和总结只显示一个肌群条目，相关活动方向合并到详情；处理队列按一个处理单元执行，避免重复松解 |
| 处理5→8且停止后不回落 | 结束本次自助处理并给专业评估出口，不再返回整套检查 |
| 训练2→4，停止后回落 | 只允许退阶一次；采用退阶后返回原训练阶段 |
| 训练退阶后仍加重 | 不再进入第二次退阶，改为聚焦复查或停止 |
| 后续康复训练加重 | 聚焦复查后回到该次康复的训练/处理流程，不落入第一次康复页面 |
| 当天晚些时候或次日加重 | 追加到本次观察记录，不增加康复次数 |
| 异常反应中途保存并恢复 | 恢复来源、回答、相关检查、评估版本和原流程位置 |
| 连续两次异常反应 | 每次评估版本递增；任一旧版本方案均不能跨版本执行 |

## 继续试用时重点收集

1. 用户在哪个字段最常选择“说不清”；
2. 评估6项是否仍然太多，哪一项最难理解；
3. 核心处理3项是否仍然显得拥挤；
4. 哪些主诉在处理后分数下降，哪些处理方向没有即时变化；
5. 居家训练能否完成，是否需要更清楚的退阶；
6. 专项检查和骨性风险问题是否引起误解或过度担心。
7. 普通用户是否能理解“主动范围仍小于健侧”和训练退阶；
8. 组合处理后，用户是否会误认为每一项都已被单独验证有效。
9. “轻柔松解 + 主动控制”是否能被理解为一个处理单元，而不是正式力量训练。

## 极端与边界场景回归

| 类型 | 输入或条件 | 应有结果 |
| --- | --- | --- |
| 最少信息 | `疼` | 不生成部位、侧别或动作；从最关键缺项开始逐题补充 |
| 口语部位 | `脚脖子崴了` | 识别为踝足，不误判为颈部 |
| 没有固定动作 | `脚踝一直酸疼，很久了，说不清什么时候疼` | 允许选择“说不清 / 没有固定动作”后继续，不强造复测动作 |
| 情绪化描述 | `走路一瘸一拐，抬脚也不行，踩地也不行` | 收集到走路或负重场景，不把情绪词当诊断 |
| 双侧 | `两边膝盖都疼，走路多了更明显` | 记录双侧并能继续；活动范围按左右表现比较 |
| 多部位 | `膝盖疼，脚踝也疼` | 先选本次优先部位，不混合生成一套方案 |
| 全阴性 | 无固定诱发动作且膝踝评估均无异常 | 不虚构问题或处理；给低刺激基础活动，并提示症状仍在时返回补充发生经过和诱发动作 |
| 全阳性 | 高分疼痛、多个动作无法完成、专项检查异常 | 压缩问题清单，停止叠加自助处理并给出医学/线下评估出口 |
| 麻电或感觉变化 | 普通用户选择麻、电、感觉异常 | 不生成自助神经手法，保存记录并建议线下确认 |
| 专业模式 | 专业人员替他人检查且可判断被动范围 | 主动与被动分开；被动仍受限才进入对应关节松动 |
| 重复动作 | 主诉“勾脚疼”，评估也有勾脚 | 共用一条问题与一次复测；力量项只比较发力后是否更重 |
| 复诊 | 第二、三次康复仍有肿胀、活动受限和疼痛 | 肿胀单独按时间比较；即时处理只保留可当场验证的处理；训练单列 |
| 最终复测 | 训练结束 | 再做一次主诉动作并显示首评、处理后、训练后三个分数 |
| 空相关检查 | 异常来源没有直接匹配ID | 使用当前区域第一个有效基础检查兜底；若区域本身无检查则返回补充信息，不显示空白页 |
| 相同答案复查 | 聚焦复查答案与旧值完全相同 | 用户点击确认即可完成新版本，不能因值未变化而卡住 |
| 新麻电或明显无力 | 任一处理、训练或次日观察出现 | 立即停止，不退阶、不继续处理，保存并建议专业评估 |
| 全部不会做 | 关键活动、力量与功能均选择不会做或无法判断 | 保持证据不足，提供具体补充入口或专业协助，不显示“没有问题” |
