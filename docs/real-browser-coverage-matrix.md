# RehabMind 真实场景覆盖矩阵

更新时间：2026-08-21

## 使用口径

这是一张验证矩阵，不是新的产品规则。每一行都必须回答五个问题：

1. 设计规则要求什么；
2. 用户通过什么真实场景触发；
3. 现在已有哪一层证据；
4. 当前是否已经能重复验证；
5. 下一步缺什么。

### 状态定义

| 状态 | 含义 |
| --- | --- |
| 覆盖·本轮浏览器 | 本轮已用当前页面和当前脚本重新执行，并有页面结果记录 |
| 覆盖·历史浏览器 | 旧走读记录中通过，但当前没有独立可重复脚本 |
| 覆盖·规则/服务层 | 有纯规则、契约或服务测试，没有真实页面证据 |
| 部分覆盖 | 有浏览器路径，但缺少关键分支、反向断言或当前脚本复现 |
| 未覆盖 | 当前没有足够的规则、页面或部署证据 |
| 已选·待执行 | 已进入当前批次，但固定脚本和真实证据尚未完成 |
| 功能缺口 | 页面入口或功能本身尚不存在，不能用测试替代实现 |

“历史浏览器”不等于“当前自动回归”。“规则/服务层”也不等于“用户流程通过”。

## 执行原则

- 修改某条设计规则时，必须运行该行对应的规则测试和真实浏览器场景；
- 历史浏览器记录只能作为参考，不能替代当前脚本；
- 每条浏览器场景都要有“应出现”和“禁止出现”两类断言；
- 每发现一个真实缺陷，就在矩阵新增或更新一行，并先补回归测试再修实现；
- 预览环境的保存、恢复、隔离和权限测试不能用本地 D1 通过替代。
- 发散场景先按页面证据和 P0/P1 优先级筛选，再并入 A/B 批次；不把整张发散库一次性当成待执行清单。
- 每个场景执行完成后立即回写状态、脚本、断言和证据；矩阵状态没有更新时，不得口头宣称覆盖完成。

## 测试实现边界

- 规则行应绑定纯核心测试；流程行应绑定状态测试；页面行应绑定固定 `scenarioId` 的真实浏览器脚本；数据行应绑定服务/API 或预览环境证据。
- 共享 helper 只提供导航、教程处理、错误收集和证据保存，不替场景决定选项或隐藏页面状态。
- `tests/real-browser-audit-contract.test.mjs` 只能证明脚本和页面契约仍存在，不能单独算作一次真实浏览器执行。
- 当前通用走读脚本仍有探索性质；只有明确选择、关键页面断言、应出现/禁止出现断言和稳定运行记录齐全后，才能把矩阵状态改为“覆盖·本轮浏览器”。
