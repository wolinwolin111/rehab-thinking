# 01 · 产品设计与用户流程

> 文档状态：现行 ｜ 建立：2026-09-06 ｜ 事实来源：stages 组件、workflow-profile、workbench 实测（行号截至本日）
> 本文定义产品范围、双模式与用户流程。决策规则见 02，内容文案见 04，编排状态见 05。

## 1. 定位与范围

RehabMind 是**下肢康复辅助决策工具**：不替代诊断，用一次结构化对话把"该查什么、怎么处理、何时复测、练到什么程度、什么时候再来"变成可执行任务。

- **首发范围**：大腿至足部一个大部位入口（膝＋踝足两个功能模块，含大腿/小腿局部）；桌面与 320/360/390/412/430px 手机网页；Android WebView 壳在网页验收后构建。
- **本地规则引擎**：无大模型、无视觉 AI（预留见 09）；骨盆、上肢、颈肩腰未开放，入口必须明说。
- **案例学习模式本期不开放生产入口**（workflow-profile 保留 study 能力位供内部走读）。

- **能力依赖**：关节处理必须先有被动活动度；取消被动即级联清除关节处理与相关证据（:71,:79-85）。
- **学习解释是纯展示层**：开关前后按钮、结果、路径必须完全一致（决策规范裁定）。
- 两套界面共享主诉解析、安全规则、finding、候选、复测与训练核心——禁止复制"专业版临床规则"。

## 3. 自助模式：六步流程

症状信息 → 关键确认 → 评估检查 → 处理复测 → 训练居家 → 康复总结。前一步未完成不可跳转（导航锁定）；每步可返回修改，上游变更使受影响下游失效（SYS-STATE-001）。

1. **症状收集**：口语输入＋解析候选确认（宁滥勿缺）；一次只追问一个缺项；多选停留当前题，"选好了"才推进；评分滑条未操作不记录、拖定即写入（不二次确认）。
2. **关键确认**：安全信号、影像/医嘱结论（结构异常未获医生允许→锁定评估入口但可保存）、既往处理、目标分级 1-5。
3. **评估检查**：一卡一屏＋进度；作答按钮按动作定制（见 04 §5）；"做不到"→原因追问（疼/没力/担心/不会做）；疼痛记录三层＝位置＋性质＋0-10 分；专项检查异常只说明"不能单独判断结构问题"并提示线下确认。
4. **处理复测**：处理队列按 02 §7 生成；"开始复测"锁定本轮快照；主诉复测承接处理前分数（5→4 后显示"处理前 4/10"）；加重即停止并给出口。
5. **训练居家**：分期见 02 §9；第一组反馈四分支；训练前准备只在本次仍紧张或既往有效时出现；居家放松按 tags 归并。
6. **康复总结**：问题台账逐条去向（处理/训练/复查/补查/医学确认）；复诊窗口分档；保存生成追加式历史。

## 4. 康复思路模式：五阶段工作台

症状与安全—评估—处理与阶段复测—训练—总结。每阶段三出口（完成阶段/保留待确认/保存后结束）；评估分必查/建议/可选，必查安全信息只锁定依赖它的高风险操作；阶段工作台有明确阶段卡，进入评估不出现空白（SYS 场景）。

## 5. 页面与交互契约

- **BodyMark**：markId/symptomKind/side/regionId/surface/归一化坐标/source/失效事件；complaintSide≠worseSide≠prioritySide；移除不删档改 invalidated，重加生成新档（body-mark-core.ts:84-106）。
- **ScoreRecord**：state（unselected/confirmed/superseded/not-applicable）——**0 与未选择严格区分**；只有 confirmed 且动作/方向/侧别/场景/量表版本全同才比较（score-record-core.ts:257-269）；superseded 不物理删除。
- **双侧**：左右位置同时保留、优先侧必选；同目标合并一张双侧卡分侧记录分侧复测（SYS-BILATERAL-001~004）。
- **疼痛记录**：位置图＋性质＋分数三层；"看不出来/做不了"是有效记录不是失败。
- 移动端：无页面级横向溢出是验收门槛。

## 7. 不做清单

不输出诊断；不因改善清除其他问题；不用单个特殊测试替代影像或专业评估；不默认冰敷（撞伤路径）；不把"处理过"当"没问题"；不把复诊当"有效验证"；派生标签不落盘；空队列≠没有问题。
