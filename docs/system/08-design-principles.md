## 1. 核心设计原则

1. **单一事实源**：一个动作的叫法只在词根定义一次（04）；一条业务规则只在一份文档完整定义（00 维护规则）；一项业务事实只有一个状态所有者（05 §3）。
2. **值契约锁死**：决策层输入的枚举（选项值、finding 结果、归因态）永不改字面；改的只是显示标签（04 §5、02 §C）。
3. **数据可信度四类**：原话永久保留／解析候选须确认／确认事实进决策／系统推断只生成检查。
4. **安全优先序**：安全分流＞主诉＞评估推断；评估更差侧只能提醒不能静默替换（02 §11）。
5. **候选是反应试验不是病因**：单项阳性不生成结构诊断；"关键完成"≠病根（03 §9）。
6. **追加式历史**：处理事实不删除只 superseded；加重事实以 symptomHistory 追加不可抹除（T-10）。
7. **逐字保真迁移**：内容搬家不换措辞，剂量从句子抽出为数据字段；改动必须有 owner 裁定编号。
8. **最小充分**：不为"文件变少/抽象变多"重构；先抓基线再估工（D4-1）；无需求不启动休眠阶段（refactor-use-decision-engine）。

## 2. 编码与验证纪律（过程教训固化）

1. **等价性验证禁止循环论证**——迁移类改动的"旧值"必须取自 git 基线（`git show <pre>:<file>`），不得从改动后的新位置读取（步骤 1 空数组回归的根因）。
2. 格式化脚本改数据后必须逐条比对原始表，tsc 通过不等于内容无损。
3. 真实浏览器/真实用户输入是验收必需（套件绿≠界面对）。
4. 禁止把 node_modules 以 junction 接入 git worktree（`worktree remove --force` 会沿链接清空真实依赖）。
5. PowerShell 内联 node -e 含中文/正则/引号必坏——写临时脚本执行。
6. 未推送提交封存：批次 3 曾先斩后奏被叫停，此后"裁定完再动"。
