# RehabMind 动作演示系统完整方案

> 状态：后续素材方案。当前 Demo 仅保留视频接口，不属于首发完成项。

## 1. 系统目标

动作演示系统不是独立的视频库，而是康复决策流程的一部分。它需要回答五件事：

1. 现在做什么。
2. 怎么做。
3. 做的时候观察什么。
4. 什么结果说明这个方向值得保留。
5. 无变化或加重时下一步怎么调整。

系统面向正在学习运动康复或希望拓展康复业务的健身、普拉提、瑜伽等教练。内容不能默认用户已经掌握专业触诊、特殊测试和关节松动，也不能把单个动作包装成治疗某种疾病的方法。

## 2. 核心原则

### 2.1 演示服务于决策

每个演示必须挂在以下流程之一：

```text
评估检查 → 记录结果
处理试验 → 重复原动作复测
训练动作 → 下次比较能力变化
```

不能只给出“动作名称 + 视频”。

### 2.2 一次只解决一件事

- 评估演示只告诉用户如何完成当前检查。
- 处理演示只展示当前候选来源的单变量试验。
- 训练演示只展示当前阶段需要的动作、组数、个数以及必要的时长或距离。
- 原因解释放在知识详情中，不占据主要操作界面。

### 2.3 三帧演示优先，真人视频补充

默认展示体积很小的三帧演示；用户需要更多细节时，再点击查看真人视频。

```text
起始位置 → 动作过程 → 终点 / 观察位置
```

这可以保证手机端加载速度，也避免每张卡片都出现一个占空间的视频播放器。

### 2.4 候选来源，不生搬硬套

线下记录中有效的方法进入候选库，但必须通过原活动方向、原疼痛动作或原功能任务进行验证：

- 改善：保留，并用主动训练巩固。
- 不变：不继续加力，换另一个候选来源。
- 加重：撤回本次变量，降低难度或返回评估。

## 3. 演示内容分级

### A 级：用户可独立完成

适用于大部分主动检查和训练：

- 关节主动活动。
- 健患侧比较。
- 踝泵、提踵、臀桥、鸟狗、墙面滑手等训练。
- 扶持下重心转移、坐站、浅蹲和低台阶。

展示内容可以完整包含动作、组数/个数、必要的时长或距离、进退阶和常见代偿。

### B 级：需要教练或他人协助

适用于低风险的协助检查：

- Thompson、小腿挤压等需要观察两侧差异的测试。
- 部分肩关节或神经张力检查。
- 轻柔的手动位置调整复测。

必须标注：

- 谁来完成。
- 什么时候使用。
- 阳性结果看什么。
- 什么情况立即停止。
- 不熟悉动作时可以跳过。

### C 级：仅限受训者

适用于：

- 关节附属活动检查。
- 距骨、腓骨、髌骨、盂肱关节和脊柱分节检查。
- 关节松动术。
- 需要明确手法方向和等级的处理。

普通用户只看到：

```text
为什么考虑这一方向
由谁操作
做完复测什么
出现什么反应时停止
```

具体手法视频进入“受训者内容”，不能让初学者误以为照着视频用力即可。

### D 级：不提供动作演示

出现明显错位、持续远端感觉或循环异常、进行性无力、开放损伤等情况时，只展示信息保存和专业评估流程，不展示诱发测试或处理手法。

## 4. 三种演示形式

### 4.1 三帧动作图：默认形式

每个动作包含：

- 第 1 帧：起始位置。
- 第 2 帧：动作方向。
- 第 3 帧：终点与观察位置。
- 一个循环方向箭头。
- 一条最重要的观察提示。

适合：

- 主动活动度检查。
- 等长训练。
- 踝泵、提踵、重心转移。
- 肩胛控制、墙面滑手。
- 臀桥、鸟狗、坐站等路径清楚的动作。

技术形式使用 CSS、HTML 和少量关键帧，不依赖外部素材和视频播放器。

### 4.2 自有真人短视频：核心动作

用于三帧图无法完整表达的动作：

- 步态与台阶。
- 膝触墙背屈。
- 分腿蹲、髋铰链。
- 肩胛辅助上举。
- 单脚控制和后期跑跳训练。
- 需要展示手位的协助检查。

每条视频标准：

- 10～20 秒。
- 静音也能看懂。
- 固定机位和统一背景。
- 正面或侧面只选最能说明动作的角度。
- 开头直接进入起始位置。
- 不制作长篇口播。
- 画面字幕最多三条：怎么做、看什么、何时停止。

### 4.3 第三方公开视频：临时备用

只作为自有内容完成前的占位方案：

- 只嵌入允许嵌入的视频。
- 不下载、不剪辑、不重新托管普通公开视频。
- 记录来源、作者、链接、授权状态和最后检查时间。
- 第三方链接失效时自动回退到三帧演示。

## 5. 用户界面结构

### 5.0 症状信息收集入口

用户先用自己的话描述问题，系统不先展示一整页固定选项。流程为：

```text
自由描述
→ 提取并展示已收集信息
→ 用户确认或返回修改
→ 只追问会改变安全判断、评估选择或目标阶段的关键缺口
→ 进入评估
```

已收集信息分成三类显示：

- **当前主要问题**：最困扰用户的疼痛、不适、活动受限或功能异常。
- **恢复目标**：消肿、减轻疼痛、恢复日常生活、恢复一般运动或恢复高强度对抗；目标可以是宽泛的，不强迫用户说出某个精确动作。
- **问题复现动作**：系统根据主诉选择的安全、可重复比较动作，用于处理前后复测；它不等于恢复目标。

系统优先提取部位与侧别、开始时间、发生场景或受伤机制、症状性质、变化趋势、当前功能、影像情况和恢复目标。用户可点击任一项返回修改，也可以选择“不确定”。

没有从原话中获得的字段保持为空或“待确认”，不得预设区域、侧别、位置、问题动作、目标和评分。只有脚趾、足底、足弓等内容被主诉明确触发时，踝足评估才追加相应演示，不因为用户选择“踝足”就展示整个足部动作库。

主要疼痛或不适使用 0～10 分滑条：

```text
当前疼痛/不适程度
0  没有疼痛或不适  ━━━━━●━━━━━  10  能想象到的最严重
当前：6 分
评分时：下楼梯、患侧承重阶段
```

滑块下方动态显示当前分数所属的感受档位：1～2“刚有一点感觉”、3～4“轻微痛感”、5～6“明显难受”、7～8“很痛”、9“接近最严重”。首次收集不展示“同速度、同负重、同扶持”等复测条件，这些提示只在复测页面出现。

产品术语使用“疼痛/不适评分（0～10）”。其中疼痛属于 NRS 数字评分；挤、扯、酸、卡等非疼痛感觉沿用滑条只是为了本人前后跟踪。每次评分同时保存感觉类型和发生情境，不能把不同动作或不同感觉的分数放在一起比较。

追问采用动态数量，不用固定长问卷：

- 描述较完整：通常再问 2～4 个关键问题。
- 慢性或逐渐出现的问题：通常共 4～6 个关键问题。
- 急性损伤：通常共 5～8 个关键问题，增加受伤机制、明显轮廓异常、承重/使用能力、影像等安全问题。

界面显示“还需确认约 2 项关键信息”这类进度，不显示让人焦虑的长题号。满足以下条件即可停止追问：完成必要安全筛查、确定主要问题和恢复目标、能够选择第一批评估项目。活动度、力量、触诊和特殊测试留到评估流程，不在症状收集阶段提前问完。

### 5.1 动作卡片默认状态

手机页面只显示：

```text
[三帧演示]
动作名称
组数、个数与必要时长
观察什么
[看真人演示]
```

“为什么做”“详细原理”和扩展知识不放在默认卡片中。

### 5.2 全屏演示层

点击真人演示后打开全屏或接近全屏的演示层：

- 视频或三帧大图。
- 动作名称。
- 当前组数、个数与必要时长。
- 一个主要观察点。
- 常见代偿。
- 停止条件。
- 做不了 / 太轻松两个调整入口。

退出演示后回到原流程位置，不丢失评估或训练记录。

### 5.3 评估演示卡

评估卡只保留：

- 怎么做。
- 看什么。
- 结果按钮。
- 返回上一项。

例如踝背屈：

```text
怎么做：先做健侧，再做患侧，脚跟保持接触地面。
看什么：患侧范围是否更少，是否出现刺痛或卡住。
结果：接近健侧 / 患侧更少 / 刺痛 / 卡住 / 暂不测试。
```

### 5.4 处理试验卡

```text
页面标题始终为：针对性处理

先记录原动作、条件和 0～10 分
→ 查看本次处理演示
→ 只完成一个候选处理
→ 在相同条件下重复原动作并再次评分
→ 6 分变为 3 分：下降 3 分 / 50%
→ 系统自动生成：保留 / 换下一项 / 停止
```

处理卡只把实际动作放在主视觉层级，例如“对相关紧张肌肉做 30～60 秒轻柔松解”“针对受限方向做轻柔单方向关节松动”“垫高小腿并做 10～20 次缓慢勾脚和下压”。操作权限、力度、停止条件、观察和复测放在次级提示，不能用一大段解释淹没动作。

活动度处理不能只问“松解后有没有改善”，也不能为每个受限方向复制一套相同肌肉处理。系统根据拮抗肌紧张、同功能肌疼痛/紧张、力量和原动作反应，只选一组最直接的肌肉处理，随后一次性比较它关联的全部未解决方向：主动、被动都接近健侧的方向退出；被动接近健侧但主动仍较少时转入该方向主动控制；只要被动仍较少，无论有改善还是没有变化，都直接转入对应关节松动，不再轮换其他肌肉。关节松动后再次比较实际处理的方向，再回到原问题动作。

进入复测后，主指令固定为“现在复测：回到刚才的疼痛或受限动作”。相同幅度、速度、负重和扶持只作为次级提示；动作不安全或不适合重复诱发时，改为稍后或下次跟踪。前台提问使用普通用户能听懂的问句，不能把内部规则名直接当标题；不能明显改变当前评估或处理路线的问题不单独追问。

不能用处理演示替代复测。疼痛动作不再增加一组“更顺/无变化/加重”按钮，而是由同一条评分的前后变化自动生成状态。活动度另外比较范围；肿胀、力量和压痛按恢复时间跟踪。肿胀每次康复只显示和登记一次，不复制到后续每个处理候选中。

### 5.5 训练卡

训练卡根据当前能力提供：

- 当前版本。
- 建议组数与个数。
- 做不了时的退阶。
- 太轻松时的进阶。
- 次日反应记录。

单次方案不能只剩一个动作：急性反应或基础症状目标至少 2 个，恢复正常生活及以上至少 3 个，优先覆盖关节活动、基础力量/控制、承重或生活功能。当前阶段不能完成较高层动作时展示基础版。

系统给出的是第一次尝试的起点，不是固定处方。例如低负荷控制可从每组 10～15 个、2～3 组开始。完成第一组后，只记录四项：实际完成个数、动作是否变形、症状是否增加、感觉还能规范完成几个。

- 低于建议下限且已经变形或症状增加：降低阻力、难度或每组个数。
- 完成建议范围，约还能规范完成 2～3 个：保持当前版本。
- 达到上限仍很轻松，约还能完成 5 个以上：小幅增加难度或阻力。
- 连续两次训练和次日反应都可接受：一次只增加个数、阻力、动作难度或训练量中的一个变量。

力量和平衡训练不要求当场变强；活动范围和疼痛动作才使用即时复测。

## 6. 动作库的数据结构

每个动作使用统一数据模型，不把文字和视频地址散落在页面代码中。

```ts
type MotionDemo = {
  id: string;
  title: string;
  region: "ankle" | "knee" | "hip" | "back" | "shoulder";
  category: "assessment" | "treatment" | "training";
  access: "self" | "assisted" | "trained-only";
  goal: string;
  startPosition: string;
  steps: string[];
  observe: string;
  stopRules: string[];
  sets?: string;
  reps?: string;
  holdSeconds?: string;
  distance?: string;
  firstSetAdjustment?: {
    completedReps: number;
    formChanged: boolean;
    symptomChange: "better" | "same" | "worse";
    goodRepsInReserve: number;
  };
  immediateRetest?: string;
  delayedRetest?: string;
  easier?: string;
  harder?: string;
  frames: {
    start: string;
    middle: string;
    end: string;
  };
  video?: {
    ownUrl?: string;
    externalUrl?: string;
    posterUrl: string;
    duration: number;
  };
  attribution?: {
    author: string;
    license: string;
    sourceUrl: string;
  };
  review: {
    clinicalReviewer: string;
    reviewedAt: string;
    version: string;
    status: "draft" | "reviewed" | "published";
  };
};
```

患者评分记录与动作库分开保存，但通过问题复现动作 ID 关联：

```ts
type SymptomRatingRecord = {
  symptomId: string;
  symptomType: "pain" | "ache" | "pressure" | "pull" | "stiffness" | "other";
  score: number; // 0～10
  context: "rest" | "reproduction-task" | "after-activity";
  reproductionMotionId?: string;
  condition: {
    range?: string;
    speed?: string;
    load?: string;
    support?: string;
  };
  timing: "before" | "after" | "later-same-day" | "next-day" | "next-session";
  recordedAt: string;
};
```

前后变化只能在 `symptomId`、情境和动作条件相同时计算；系统保存原始分数，不只保存“改善”结论。

## 7. 第一批动作清单

### 7.1 踝足

评估：

- 背屈、跖屈、内翻、外翻健患侧比较。
- 扶持下重心转移。
- 四步与短距离步态。
- 坐姿/双脚提踵。
- 扶持下单脚站。
- 膝触墙背屈。
- 低台阶上步和下步。

训练：

- 踝泵和四向主动活动。
- 四方向等长与弹力带训练。
- 坐姿、双脚、偏患侧和单脚提踵。
- 脚跟到脚趾步态。
- 前后脚站、单脚站和多方向触地。

### 7.2 膝关节

评估：

- 主动伸直和脚跟滑动弯曲。
- 坐姿伸膝控制。
- 屈膝脚跟压地。
- 坐站、浅蹲、台阶。
- 髋旋转和踝背屈对比。

训练：

- 主动伸膝、股四头肌等长。
- 臀桥和单腿臀桥。
- 坐站、浅蹲和分腿蹲。
- 低台阶上步、下步和离心控制。
- 提踵和单脚控制。

### 7.3 髋、骨盆和腰背

评估：

- 腰背前屈、后伸、侧屈和旋转。
- 髋内外旋、屈髋。
- 臀桥、鸟狗和髋铰链。
- 坐站、走路和弯腰取物。

训练：

- 呼吸与骨盆控制。
- 臀桥、蚌式开合、鸟狗。
- 站立屈髋和髋铰链。
- 分腿站、单腿屈髋和负重髋铰链。

### 7.4 肩部

评估：

- 前屈、后伸、外展、水平内收、内旋和外旋。
- 墙面推和肩胛控制。
- 颈椎、胸椎和前臂旋转。
- 举手、摸后脑、手到腰后和拧毛巾。

训练：

- 肩袖内外旋等长。
- 墙面滑手。
- 肩胛后缩下沉。
- 前锯肌墙面推。
- 轻阻力斜向上举和分级过顶训练。

## 8. 内容制作流程

### 8.1 从线下记录建立选题

```text
高频评估项目
→ 高频异常结果
→ 常用处理候选
→ 常用训练巩固
→ 是否需要动作演示
```

优先制作会反复使用、动作容易被误解、或需要观察代偿的内容。

### 8.2 编写动作脚本

每个动作先写一张不超过一页的脚本：

- 使用场景。
- 起始位置。
- 三个以内的动作步骤。
- 唯一主要观察点。
- 常见代偿。
- 停止条件。
- 复测动作。

### 8.3 制作三帧版本

- 使用统一人物比例和颜色。
- 固定相机视角。
- 需要比较左右时使用镜像布局。
- 用箭头表示运动方向。
- 红色只用于停止或错误提示，不用于普通装饰。

### 8.4 拍摄真人版本

零成本设备：

- 一部手机。
- 固定支架或稳定桌面。
- 纯色墙面。
- 自然光或已有室内灯。
- 免费剪辑软件。

每次集中拍摄同一身体部位，统一服装、背景、距离和机位。

### 8.5 压缩与导出

- 主文件保留高质量原片。
- 网页版本使用 MP4/H.264。
- 竖屏建议 720×1280；横向动作可使用 960×720。
- 每条目标大小控制在约 1～4MB。
- 单独导出 WebP 封面。
- 视频默认不自动播放，点击后才加载。

### 8.6 审核与发布

每条动作至少经过：

1. 动作准确性审核。
2. 适用人群和停止条件审核。
3. 手机画面和字幕审核。
4. 版权与出镜授权审核。
5. 上线后版本记录。

## 9. 零成本技术架构

### 9.1 初期

- 三帧动画直接放在前端代码中。
- 动作说明保存在 TypeScript 或 JSON 文件中。
- 少量真人视频可放在当前站点静态资源中。
- 第三方视频仅作为备用链接。

这一阶段不需要数据库和后台管理系统。

### 9.2 动作数量增加后

推荐使用 Cloudflare R2 存放自有视频：

- 免费额度内可存放早期动作库。
- 外网流量不收费。
- 视频地址仍由动作数据文件管理。
- 前端按需加载，不进入首屏资源。

官方定价说明：<https://developers.cloudflare.com/r2/pricing/>

### 9.3 YouTube 备选

自有视频可以上传为“不公开”并嵌入网页：

- 使用 `youtube-nocookie.com` 隐私增强模式。
- 保留本地原始视频，避免以后更换平台时丢失素材。
- 不把“不公开”当成真正的隐私控制，获得链接的人仍可分享。

官方嵌入说明：<https://support.google.com/youtube/answer/171780>

### 9.4 不建议作为长期主库

- Vimeo 免费账户容量有限，适合演示，不适合完整动作库。
- GitHub Raw 不适合视频分发。
- 随机第三方康复视频可能被删除、禁止嵌入或改变内容。

## 10. 素材版权与出镜管理

### 自有拍摄

- 明确拍摄者、出镜者和产品使用范围。
- 保存出镜授权。
- 不在画面中出现患者隐私、病历或无关人员。
- 产品拥有可持续使用和修改的源文件。

### 开放授权素材

- 每个文件单独记录许可。
- CC BY需要署名。
- CC BY-SA修改后可能需要使用相同许可。
- CC BY-NC不适合作为未来商业产品的核心素材。
- 不确认许可时，不下载和重新发布。

Wikimedia Commons复用说明：<https://commons.wikimedia.org/wiki/Commons%3AReusing_content_outside_Wikimedia/en>

## 11. 产品内的加载策略

- 首屏只加载文字和封面。
- 三帧动画进入视口后才播放。
- 真人视频点击后才请求文件。
- 同一页面只允许一个视频播放。
- 关闭演示层时停止视频。
- 网络较慢时自动保留三帧版本。
- 视频加载失败时显示动作图和文字，不显示空白播放器。
- 用户可以选择“减少动画”。

## 12. 反馈和数据

早期不需要复杂数据分析，只记录有助于改进动作内容的事件：

- 是否打开真人演示。
- 是否选择“做不了”或“太轻松”。
- 哪个动作经常出现“看不懂”。
- 处理后原动作改善、不变或加重。
- 次日是否出现反弹。

不以播放次数判断临床有效性；核心指标是用户是否完成正确复测，以及动作是否帮助其选择下一步。

## 13. 分阶段上线

### 阶段一：三帧动作库

目标：覆盖当前 Demo 的基础流程。

- 完成 20 个核心动作。
- 统一动作卡数据结构。
- 统一手机全屏演示层。
- 第三方视频作为临时补充。

验收标准：不打开视频也能完成全部基础流程。

### 阶段二：自有真人视频

目标：替换最常用、最容易误解的第三方内容。

- 拍摄第一批 20～30 个动作。
- 完成统一封面、字幕和压缩。
- 接入按需加载和失败回退。
- 建立出镜授权与版本表。

验收标准：踝、膝、腰髋和肩部核心训练不依赖外部视频。

### 阶段三：评估与手法演示分层

目标：建立专业等级。

- 补充协助检查视频。
- 建立“仅受训者”内容标识。
- 将关节松动与处理演示绑定到明确进入条件和复测动作。
- 增加内容审核记录。

验收标准：用户能够明确分辨“可以自己做”“需要协助”“仅限受训者”。

### 阶段四：动作管理工具

当动作超过约100个、多人参与维护时，再建设后台：

- 搜索和筛选动作。
- 修改组数、个数、必要时长和提示。
- 替换视频。
- 审核与版本发布。
- 查看失效外部链接。

早期不建议先开发后台，避免把时间花在尚未稳定的内容管理上。

## 14. 推荐的当前实施路线

```text
现有 CSS 动画
→ 升级为三帧标准组件
→ 建立统一动作数据文件
→ 覆盖20个核心动作
→ 用手机拍摄第一批自有视频
→ 上传R2或YouTube不公开
→ 逐步替换第三方视频
→ 再扩展协助检查与受训者手法内容
```

这条路线平台费用可以保持为零，主要投入是内容整理、拍摄和专业审核时间。它也不会因为某个第三方视频下架而让康复流程无法继续。

## 15. 最终验收标准

完整动作演示系统应达到：

- 所有核心评估和训练均有三帧演示。
- 复杂动作有自有真人视频。
- 每个动作都写明观察点和停止条件。
- 处理演示必须绑定原动作复测。
- 处理页标题始终为“针对性处理”，实际动作显著高于提示信息。
- 肿胀每次康复只进入一次管理与跟踪，不在每项处理后重复出现。
- 训练动作提供退阶和进阶。
- 基础目标至少 2 个居家动作，正常生活及以上至少覆盖 3 个能力维度。
- 手机端默认不被视频播放器占满。
- 外部视频失效时仍可完成流程。
- 所有第三方素材具有可追溯授权记录。
- “自行完成、需要协助、仅限受训者”清楚区分。
- 动作版本和专业审核状态可追踪。
