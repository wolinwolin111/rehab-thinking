# 膝关节与踝足首批决策追踪表

> 目的：证明每一项向用户收集的信息，确实改变了后续检查、处理、复测或训练。只记录但不改变路径的信息，不进入首轮问答。

## 1. 本轮重构边界

- 首批只验证膝关节和踝足；
- 原始康复记录作为候选来源、检查顺序和反应实验依据，不作为固定处方；
- 普通用户只回答能看到、能做到、能感觉到的事实；
- 系统内部保存专业关系和来源病例，前台只显示当前要做的事；
- 用户说“不知道”时保留未知状态，不能把未知自动当成正常，也不能用“说不清”生成复测动作。
- 每项检查必须有明确触发信息、结果出口和复测目标；没有进入任何后续决策的信息不设为首轮必答。

## 2. 信息怎样进入后续流程

| 收集信息 | 影响检查 | 影响处理 | 影响复测与训练 |
| --- | --- | --- | --- |
| 不舒服的具体位置 | 只调用该位置及必要相邻区域；明确足趾局部问题时不做完整踝足套餐 | 优先位置最近、资料关系最强且尚未尝试的候选 | 复测只保留原来异常且与本轮处理相关的动作 |
| 发生时间与受伤经过 | 决定是否先做急性损伤和骨性风险确认；急性高刺激期减少力量和高负重检查 | 决定是否先做肿胀管理、轻柔活动，暂缓高刺激处理 | 急性期训练从低负荷开始；肿胀按晚些时候或次日跟踪 |
| 感觉性质 | 酸、扯、紧优先补肌肉紧张与发力；刺、胀优先确认局部刺激和持续范围；麻、电记录分布和力量变化 | 改变肌肉、负荷管理、神经或关节候选的排序 | 复测使用相同动作、位置、感觉和评分，不把不同感觉合并 |
| 肿胀、淤青位置 | 肿胀过大时活动度只做可用范围，不强求末端 | 肿胀管理当次只出现一次 | 不在每项手法后复测；晚些时候或次日比较同一位置 |
| 按压痛位置 | 缩小局部检查范围；不反复重压 | 避开明确刺痛中心，不能因为压痛直接诊断结构损伤 | 作为跨次跟踪，不要求当场消失 |
| 当前会不舒服的动作 | 优先调用同一功能动作和直接相关的活动、力量检查 | 主诉优先，按位置、性质、动作和检查结果排列候选 | 成为第一复测动作；分数下降即记录有效方向，不要求降到 0 分 |
| 没有固定动作 / 说不清 | 不生成虚假的主诉动作，继续做少量高相关检查 | 只有检查复现了平时熟悉症状，才进入针对性症状处理 | 由检查动作生成具体复测目标；否则只跟踪活动范围或功能表现 |
| 主动活动范围 | 确定具体受限方向；普通用户不要求被动检查 | 普通用户先进入肌肉比较和主动控制；专业用户再结合被动结果决定关节候选 | 同方向范围与不适一起复测；达到健侧后退出该方向 |
| 被动活动范围 | 仅专业人员给别人检查时使用 | 被动接近健侧、主动仍小：进入控制训练；主动被动都小：肌肉与关节都进入候选 | 关节处理后继续比较主动、被动和原主诉 |
| 发力表现 | 只检查与主诉动作、位置或受限方向有关的力量 | 发力疼进入症状处理；单纯力量弱不要求当场处理改善 | 力量弱进入训练和下次复查，不在每项手法后即时复测 |
| 功能动作 | 分开记录能否完成、是否晃动或借力、是否出现不适 | 不适进入症状处理；晃动或借力进入活动度、力量和控制路径 | 同一动作最多建立一个复测目标，训练按能力逐级出现 |
| 特殊检查 | 只由受伤机制、局部位置和伴随表现触发 | 阳性线索改变医学确认优先级，不直接生成结构诊断 | 决定是否先结合影像或专业评估 |
| 恢复目标 | 决定需要检查哪些功能差距，不决定首次直接做高阶动作 | 不改变现场手法顺序 | 训练按基础症状、生活、一般运动、高强度运动逐级包含 |

## 3. “说不清”怎样转成可用复测目标

```text
最开始没有固定动作
→ 完成一项高相关检查
→ 检查是否出现不适
→ 在图上标记位置 + 选择感觉 + 记录分数
→ 询问“这是平时困扰你的那种感觉吗？”
   ├─ 是：建立具体复测目标，例如“把脚背向上勾时，右外踝前方刺痛 5/10”
   ├─ 不是：只作为辅助发现，不当作主诉反复处理
   └─ 说不清：保存活动范围或动作表现，不强行建立疼痛复测
```

多个检查都复现熟悉症状时，最多保留 1～2 个复测目标，按以下顺序选择：

1. 与日常主诉最接近；
2. 能稳定重复；
3. 与当前处理候选直接相关；
4. 操作简单、风险低。

| ANKLE-R07 | 不会做、找不到感觉或明显借力 | 记录完成个数和动作表现 | 降低体位、范围、阻力或复杂度，不要求完成预设版本 | MULTI-002 |

## 6. 处理与复测不再采用通用回退标题

- 主诉动作明确：复测原主诉动作；
- 主诉动作与某个活动方向相同：两者共用一条记录，不重复处理；
- 主诉动作不明确：只使用确认复现熟悉症状的检查动作；
- 检查动作标题必须使用用户刚才执行的说法，例如“把脚背向上勾”，不能显示“说不清”“当前相关方向”或规则名称；
- 一项处理影响多个已异常方向时统一复测，但只显示本轮原来异常、直接相关且尚未退出的项目；
- 一次以主要目标为核心；相邻且共同影响同一问题的配合区域可以组成短单元，只记录组合有效和主次，不能分别归因；
- 分数下降即记录该处理方向有效；仍未完全解决时继续其他未重复候选；
- 活动范围尚未接近健侧时，即使主诉已经减轻，也继续处理剩余活动问题；
- 肿胀、按压痛和单纯力量不足不进入每项处理后的即时复测。

## 7. 当前代码落地状态

- `pilot-knowledge.ts`：补齐膝 KNEE-R01～R09 与踝足 ANKLE-R01～R07 的首批来源关系；
- `pilot-decision-engine.ts`：关系参与症状补问和评估项目排序；
- `rehabmind-complete-demo.tsx`：匹配到的资料关系参与检查排序、处理候选和实际复测对象，并保存来源病例；
- `buildPilotTreatmentUnits` 已接入页面真实处理队列：只有“已审核资料关系 + 本次异常检查”同时成立时，资料处理方向才获得最高优先级；旧通用标签只作补位；
- 功能动作“做不完”已拆成疼痛、没力、担心和不会做四种出口，不再统一误判为疼痛；
- 检查页面统一使用“现在做 / 做的时候留意 / 和另一边比”等普通用户语言，内部专业名称不作为主要指令；
- 资料关系与页面真实处理卡片建立明确映射，不再只依赖模糊标签加分；
- 位置、症状和动作分别匹配，单独出现“膝”或“脚踝”不能激活同关节全部病例关系；
- 检查得到的新位置、感觉和动作优先于最开始的模糊描述，决定当前问题的处理顺序；
- 一个处理单元保留一个主要目标及必要配合目标；同一单元对应的多个异常方向在处理后统一复测；
- 所有相关候选先进入资料规则排序，再按身份预算截取，不能在排序前丢掉来源规则点名的检查；
- 资料处理候选携带自己的复测对象进入实际页面，不再只改变排序；
- 资料关系中的训练动作编号已经与实际训练库对齐，匹配关系会改变训练排序；
- 评估中出现不适时：使用局部人体图重新标记位置，不再默认复制最开始的主诉位置；
- 没有固定主诉动作时：必须确认是否复现熟悉症状，才建立疼痛复测目标；
- 处理复测：优先使用具体检查动作名称，不再把“说不清”作为复测动作。

## 8. 验收用例

### 膝内侧下楼痛

输入：右膝内侧，下楼刺痛；检查发现伸直偏小、大腿外侧较紧，下台阶复现熟悉疼痛。

必须看到：下台阶优先；大腿外侧与内侧局部候选按检查结果排序；处理后复测下台阶和膝伸直；主诉下降但伸直未接近健侧时继续活动处理。

### 急性外踝扭伤

输入：两天前崴脚，外踝肿胀、走路痛，没有足趾主诉。

必须看到：必要安全确认；肿胀管理只出现一次；检查背屈、外翻和当前承重，不自动加入足趾；即时复测疼痛和活动，不反复复测肿胀。

### 说不清具体动作

输入：右脚踝外侧不舒服，说不清什么时候出现；勾脚检查复现右外踝前方熟悉刺痛 5/10。

必须看到：最开始不显示评分；勾脚不适在图上重新定位；确认是熟悉症状后，生成“把脚背向上勾”复测目标；不能出现“说不清”复测卡片。

### 检查出现新症状

输入：原主诉为膝内侧不适；提踵检查出现足底新痛，用户选择“不是平时的感觉”。

必须看到：足底新痛进入检查记录，但不抢占膝主诉，也不生成足底反复处理链。
