# 02 原始资料转化方案

## 1. 资料来源

- `C:\Users\26259\Desktop\ai资料` 中的线下康复记录和关节受限判断资料；
- `C:\Users\26259\Desktop\康复记录整理` 中已经整理的病例、索引、修改方案和测试报告；

资料迁移前先建立文件清单。路径已经移动或不存在的文件标为“待重新定位”，不根据旧总结假装已经读取。

## 2. 四层转化

### 第一层：原始记录库

原文只读保存，并添加：

- 来源文件；
- 病例编号；
- 记录日期或阶段；
- 是否为第一次、第二次或后续康复；
- 原文完整度；
- 是否存在明显缺项。

任何缺失信息保持空白。

### 第二层：结构化病例库

每份记录统一提取：

```text
病例信息
├─ 原始主诉
├─ 症状位置与侧别
├─ 症状性质、程度和持续时间
├─ 发生经过与当前诱发条件
├─ 受影响的生活/运动功能
├─ 恢复目标
├─ 影像和医学限制
├─ 实际检查与结果
├─ 实际处理
├─ 处理后的主诉变化
├─ 处理后的活动或发力变化
├─ 居家训练
└─ 后续复查
```

每个字段需要同时记录：

- `value`：原记录内容；
- `status`：明确、否定、未知、未记录；
- `sourceQuote`：对应原文位置；
- `reviewStatus`：未审核、已审核、存在争议。

### 第三层：康复关系库

从多个病例中提取关系，而不是固定处方：

```text
主诉/动作/位置
→ 常用检查
→ 可能出现的异常
→ 尝试过的处理
→ 处理后的实际反应
→ 后续训练与功能进阶
```

每条关系记录：

- 来源病例列表；
- 出现频次；
- 是临床经验、解剖推导还是外部证据；
- 有效、无效、变差或未复测的数量；
- 适用身份；
- 目前可信度；
- 临床审核意见。

### 第四层：产品决策规则库

只有审核后的关系才能转成执行规则。规则至少包含：

- 什么信息触发；
- 哪些信息必须确认；
- 哪些信息只是加减优先级；
- “不知道”时怎样继续；
- 推荐哪项检查以及为什么选它；
- 检查可能生成哪些问题；
- 可尝试哪些处理；
- 处理后复测什么；
- 什么结果算有效、无效或变差；
- 什么时候停止该方向；
- 训练怎样由剩余问题生成；
- 来源和版本。

## 3. 资料不能怎样使用

禁止以下转化：

- 病例写过“放松鹅足” → 所有膝内侧痛都默认处理鹅足；
- 某次关节松动有效 → 普通用户也显示同样手法；
- 记录没有写复测 → 系统自动补成有效；
- 记录写“腰痛” → 强制归入单一腰关节模块；
- 从训练动作名称反推当时一定存在某项力量不足。

## 4. 资料怎样决定优先级

线下资料主要决定：

1. 某类主诉通常优先检查什么；
2. 哪些异常经常共同出现；
3. 哪些处理值得优先作为反应实验；
4. 处理后应该复测哪些主诉和异常；
5. 训练通常怎样从基础控制进阶到功能；
6. 第二次康复通常复查哪些内容。

解剖资料用于校验肌肉功能、拮抗关系和跨关节影响；权威指南用于安全和医学分流；它们补充线下记录，但不能抹掉病例来源。

## 5. 首批加工顺序

优先提取包含以下内容的病例：

- 膝内侧、外侧、前侧、后侧主诉；
- 膝伸直或屈曲受限；
- 下蹲、上下楼、走路、跑跳异常；
- 急性崴脚、外踝或内踝问题；
- 踝背屈、跖屈、内翻、外翻受限；
- 小腿、足底、足弓、脚背和足跟问题；
- 同时涉及膝、踝或髋膝踝联动；
- 有明确处理前后变化；
- 有第二次或第三次康复记录。

首批不追求把所有病例都转完。先用代表病例建立结构和审核标准，再批量迁移。

## 6. 质量控制

每条正式规则必须能回答：

- 来源于哪份资料？
- 原资料实际写了什么？
- 哪部分是总结，哪部分是推断？
- 是否有处理后反应支持？
- 是否适用于普通用户、教练还是专业人士？
- 如果信息未知，系统会不会错误跳过？

不能回答来源的问题，只能留在研究候选池，不能直接进入产品。
